# DESIGN.md

The convention every UI change in ace follows and every UI review checks. It names tokens; raw values live in the token source (`packages/themes/src/sources/*.ts`, `apps/web/src/styles/tokens.css`, `motion.css`, `glass.css`) and are documented in [docs/design/visual-language.md](docs/design/visual-language.md). The reasoning behind the current direction is in [docs/design/2026-10-14-ui-quality-proposal.md](docs/design/2026-10-14-ui-quality-proposal.md). When this file and `visual-language.md` disagree, this file wins for _what to do_; `visual-language.md` wins for _what a token is worth_. (`DESIGN-fable.md`, referenced in old comments, lived in the prototype folder and is superseded by this file.)

## 1. Principles

1. **Every element shows state the user acts on.** If it only describes the UI, it goes.
2. **Hierarchy by one step at a time.** Text tiers, weights, surfaces and hairlines each move exactly one step between neighbours; never two devices for one distinction.
3. **Colour means state.** Status hues are the only colour in lists and chrome. Project identity is monochrome ink; provider marks keep their brand colours.
4. **Edges before air.** Separate things with hairlines, weight and size before adding space.
5. **Materials, not panels.** Floating layers are glass with an edge and a shadow; content is opaque. The composer carries a soft lift shadow; buttons stay flat.
6. **Density is a setting, hierarchy is not.** Compact removes padding, never tiers.
7. **Motion confirms, never entertains.** Things arrive; they don't fly.
8. **Correct before pretty.** Never show an agent as done while any part of its tree works or waits (AGENTS.md priority 1).

## 2. Tokens

### Colour roles and text tiers

| Token                                            | Use when                                                                                              |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `--foreground` (text)                            | The thing to read: titles, answers, selected labels, values.                                          |
| `--muted-foreground`                             | Secondary: project names, descriptions, tool rows, metadata beside a title.                           |
| `--subtle-foreground`                            | Tertiary: timestamps, counts, shortcuts, placeholders, branch names.                                  |
| `--faint-foreground`                             | Decorative icons, carets, disabled-looking affordances. Never for words.                              |
| `--ring` / `--ring-foreground`                   | The accent as a fill and the label on it: primary button, checked controls, caret, Send.              |
| `--ring-text`                                    | The accent as text: links, the current view.                                                          |
| `--status-*` / `--status-*-text` via `data-tone` | Dots and words for working, needs-you, waiting, unresponsive, failed, done. The only colour in lists. |
| `--destructive` / `--danger`                     | Destructive labels; the solid danger button.                                                          |

Rules: never hard-code a colour; never put a status hue on something that is not that status; icons take `currentColor` at the row's tier.

### Surfaces and elevation

`--background` (page and reading column) → `--sidebar` / `--panel` (navigation, side panels) → `--surface-1` / `--card` / `--bubble` (grouped content, user bubble, code) → `--surface-2` / `--popover` (solid floating). Washes: `--hover`, `--active` (= `--fill`, `--fill-strong`). Elevation is an edge plus a shadow (`--float-edge`, `--float-shadow`); content never casts a shadow.

**Depth** is a separate, smaller device for things you press or type into, from the `--depth-*` tokens in `theme/tokens.ts`. Use only these; never write a one-off shadow.

| Token               | Where                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------- |
| `--depth-highlight` | Lit top edge. No control uses it: tabs, segments, buttons and the composer are flat.  |
| `--depth-dock`      | The composer's soft lift off the page (shadow only, no highlight).                    |
| `--depth-strip`     | The smaller lift of the card attached above the composer (shadow only, no highlight). |
| `--depth-raise`     | 1px rest shadow: picker previews and small badges over media (not tabs or buttons).   |
| `--depth-fill`      | Highlight and bottom shade on a checked checkbox (not buttons).                       |
| `--depth-well`      | Slight recess of text inputs.                                                         |

Pressed controls take their pressed wash (`active:shadow-none` only where a shadow remains). Rows, cards, bubbles, the sidebar, settings cards, the header, tabs and segmented controls stay flat.

### Hairlines

`--border` between rows and sections; `--border-strong` (= `--input`) on control edges and text fields. Use the separator helpers in `components/ui/rules.ts` (`toolbarEdge`, `sectionRule`, `listDivider`, `controlDivider`); don't draw ad-hoc borders. Nothing in the sidebar is ruled except the short hairline in the rail between its two groups of places: task rows are separated by space, not dividers. The frame's one edge is the canvas's own hairline (§3, Shell).

### Radius

One scale, from `tokens.css` ("Corners"); never a literal radius.

| Class                                           | Default | Use                                                                                |
| ----------------------------------------------- | ------- | ---------------------------------------------------------------------------------- |
| `rounded-xs`                                    | 4       | Tags, inline code, project marks                                                   |
| `rounded-sm`                                    | 6       | Controls ≤ 26px, tooltips, previews inset in a card                                |
| `rounded-md`                                    | 8       | Buttons, inputs, selects, rows (sidebar, menu, palette, list), segmented tab lists |
| `rounded-lg` / `rounded-card` / `rounded-popup` | 12      | Cards, popovers, menus, dialogs, bubbles, code blocks, toasts                      |
| `rounded-xl`                                    | 18      | The composer, its attached strip, the file-drop target                             |
| `rounded-full`                                  | —       | Send/Stop, avatars, accent discs, segmented control, pills                         |

Corners are fixed at this scale; there is no setting to rescale them.

**Radius agrees with padding.** The corner must never be larger than the padding beside it, or the content looks pinched into the curve:

- A surface's radius is at most its horizontal padding (a 12px-padded row takes 8, not 12 or 14).
- Pick the radius by the element's size: about a quarter of its height for controls (24px → 6, 30–36px → 8). Larger radii make a control read as a pill; use `rounded-full` if that is what you mean.
- **Concentric nesting:** inner radius = outer radius − the inset between them. A 12px menu with a 4px inset has 8px items; a 12px picker card with a 6px inset has a 6px preview; a 8px segmented list with a 2px inset has 6px tabs. When the arithmetic doesn't land on the scale, change the inset, not the radius.
- A floating ring or focus ring outside an element follows its radius automatically (box-shadow spread); don't give it its own.

### Spacing

4px grid: 2, 4, 6, 8, 10, 12, 16, 20, 24, 32, 48 (2px steps below 12 for row and control insets only). Insets `--surface-inset` (12) and `--surface-gap` (8). Row heights from `--row-height`, `--setting-row-height`, `--picker-row-height`, `--control-height`, `--composer-control`. No 14px insets.

### Type

`text-2xs` 10.5 badges · `text-xs` 12 metadata and shortcuts · `text-ui` / `text-sm` 13 controls, menus, tool rows · `text-base` / `text-md` 14 titles and the composer · `text-prose` the transcript (`--transcript-size`) · `text-lg` 18 dialog titles · `text-xl` / `text-2xl` page titles. Weights: 400 body, **500 titles and selected labels**, 600 page titles and bold in prose. `tracking-title` on titles 18px and up. Mono (`font-mono`) for branches, paths, commands, code. `text-meta` (11.5) for a row's project, branch and status lines. Themes never change type.

### Icons

Phosphor only, `regular` weight. 16px beside 13–14px text, 14px beside 12px, 12px for status glyphs (`bold` at 12px only). Provider marks keep their own colours everywhere, sidebar thread rows included; project marks are quiet (greyed and dimmed) on settled rows. When a provider has more than one account, the account's mark sits as an 11px ink bubble on the provider glyph's bottom-right corner (`ProviderAccountIcon`), its outline cut out of the glyph with a mask rather than a ring, so it reads on any surface. One account: no bubble. Thread rows never draw the bubble. Favicons and app icons at 16px with `rounded-xs`.

### Motion

`--motion-fast` hover, colour, press · `--motion-base` popovers, menus, tooltips, new rows · `--motion-slow` panels, sheets, list moves, theme cross-fade · `--motion-exit` anything leaving. Curves `--ease-out` (default), `--ease-spring` (arrivals, segmented thumbs), `--ease-sheet` (sheets), `--ease-exit`. Animate only `transform` and `opacity`. Nothing loops forever: live state (working, streaming, an agent driving a tab) is a still glyph or ink, never motion. The only `infinite` animations are the startup mark's breath, an indeterminate progress bar and a live agent's provider mark in the Summary tree, each only while what it stands for lasts (`visual-language.md`).

### Glass

Two levels. **`glass-thin`** (`.ace-floating`): menus, popovers, selects, context menus, hover cards, toasts, and the palette panel at a near-solid tint (`--glass-tint-modal`), since it adds no blur of its own over the modal backdrop. **`glass-regular`** (`.ace-glass-dock`): the composer and the cards attached above it, one material, one blur. **Solid** (`.ace-floating-solid`): dialogs, tooltips, the Work card, anything that holds content, anything opened from glass. Never glass on glass; never glass on a scrolling area; the sidebar, page and side panels are opaque. Text on glass uses the glass inks the material provides; status words keep their opaque colours.

## 3. Layout

- **Shell:** one frame. A 44px **top bar** runs across the whole window (the drag area; macOS draws the traffic lights at its left): Back, Forward and the sidebar toggle right after the lights; the title, starting where the main column starts (it follows the sidebar as it resizes or hides): the project's folder glyph, then the thread title or the page name (a delegated child names its parent first, `parent / child`). A page the sidebar's panel already names (its heading or its selected row: Skills, Automations, Chats, Settings, Code review's Inbox, Pull requests and Issues) keeps that title for screen readers only while the panel shows beside the column, so the bar doesn't say it twice; with the sidebar hidden or in a sheet the title shows again (`namedByPanel`); at the right ⋯, the screen's tools (Work/Summary) and the side panel's toggle. No hairline under it and no other header row anywhere. Under the bar: the rail (52) on the frame colour (`--sidebar`), then the **canvas** on `--background`: it begins at the sidebar's panel (darker than the chat, most of the way to the frame colour, `--sidebar-panel`; 288 by default, drag its edge 220–480; double-click resets; it scrolls without ever showing a scrollbar), which turns a `rounded-lg` (12) top-left corner with a `--border` hairline along its top and left, and runs on through the main column (content / composer) and any side panel, with one hairline between the panel and the main column (`features/shell/canvas.ts`). Only the rail and the top bar are on the frame colour. With the sidebar hidden or in a sheet, the canvas runs to the window's edge with only its top hairline, and the navigation moves to the header's left. While the side panel is docked open beside the column, the top bar splits at the panel's edge: the column's part keeps the title, ⋯ and Work/Summary, and the part above the panel is the panel's strip (its tabs, +, the tab list, full view, then the panel's toggle at the far right), on the frame colour; the panel's content starts right under the bar, and the split follows the panel's edge as it is resized. Closed, the toggle sits at the bar's right after Work/Summary. In full view the strip takes the whole bar. Where two parts meet, the bar carries a **boundary marker** (`boundaryMarker`): a 1px `--border` line 20px tall, centred in the bar, on the edge the canvas's hairline runs down: one where the sidebar meets the column, one where the column meets a side panel docked beside it, each following its edge as it resizes. A marker shows only while the parts on both sides of it are there: none for a hidden or sheet sidebar, a closed panel, full view or a phone's panel. It is decorative (`aria-hidden`), takes no pointer and leaves the bar draggable.
- **Content widths:** the transcript and the composer share `--column` (Chat width setting). Settings pages use `--settings-column`. Wizards and empty states centre a 480px column.
- **Settings page anatomy:** page title (`text-xl` 600), optional one-line description (`muted`), then `SettingSection`s 24px apart. A section is a header plus one card. The title row carries **at most one action** on the right; an Enabled toggle is the first row of the first card; other actions live in the header ⋯ menu.
- **Section header:** 13px/500 `--muted-foreground`, 6px above the card. Explanations of a whole group go in the section `note` above the card, one or two lines.
- **Setting row:** `--setting-row-height`, label (`text-ui` 500) left, optional one-line description (`text-xs` subtle) under it, the control right-aligned at a fixed width (select 160–200, text 160, number 80 + unit, toggle, segmented). Add actions are a `SettingAddRow` inside the card. Notes and footers use `SettingNote` and `SettingFooter`.
- **Rail:** the sidebar's left 52px under the top bar, always shown, on the frame colour. Top to bottom: Threads (folders: the place is the projects list), Chats (chats-circle), Spade; a short hairline (20px, `--border`); Code review, Automations, Skills; free space; the update when there is one, Settings (gear), the profile avatar. Places are bare 20px glyphs in 40px boxes, `rounded-md`, `--hover` on hover, the current place on the `--active` fill with its glyph filled; tooltips to the right with the shortcut. No labels, no tiles. Spade, until it launches, is its mark dimmed, "Coming soon" only in its tooltip; it is not a control. The only mark a place carries is an 8px dot (§5): warning while something there needs the person, blue (`data-tone="unread"`) for news not yet seen. Threads and Chats each take theirs from their own threads, and only while the person is elsewhere. Chats is current while a chat (or New chat) is open, Threads for every other thread.
- **Panel:** beside the rail, under the top bar, the current place's content under its own title row. Every place's panel is built from the same pieces (`components/ui/panel.tsx`): the title row (44px, level with the rail's first place: the place's title, `text-lg` 600, or a filter menu in its words, then its actions as 32px icon buttons with 18px glyphs); the search field under it (32px, 8px in from the panel's sides); section labels; and panel rows. Threads: "Threads", then "Everywhere" with a small caret in `text-meta` 500 muted (the project and device filter; a filter puts the project's or device's name in its place), Search (the palette), then New thread (the pencil glyph alone, its tooltip "New thread" with its shortcut); under it the tabs Inbox · Snoozed · Settled; then the open tab's list (§8). No History row: History opens from the palette and its own route. Chats: "Chats" (with more than one device connected, a caret opening a device filter of the panel's own, the chosen device's mark beside it) and New chat; "Search chats"; then the chat list (§8). Skills: "Skills", its project and Add actions, "Search skills", then its groups as folding section labels. Automations: "Automations", "Search automations" once there is one, a New automation row, then Upcoming, Paused and In threads. Settings: "Settings", "Search settings", then its pages under their group labels. Code review: Inbox, Pull requests and Issues as panel rows, the one the page belongs to selected (a pull request's or issue's page too; one opened from the Inbox selects Inbox); the pages fill the main column. A panel never repeats what the top bar says. There is no mode switch and no Back to app: the rail is the way between places.
- **Thread row (Threads panel):** every row in Inbox, Snoozed and Settled is three lines in 80px: 16, 20 and 16px with 4px between them and 10px above and below, 12px side padding, `rounded-md`, inset 8px from the sidebar edge, 4px between rows, no dividers. Rows carry no status words. Line 1 (`text-meta` muted): the project's name (no mark) with the browsing and computer-use marks right after it (they never move when the row's actions show) … then the status (`RowStatus`, from `rowStatusLook`, §5): one 16px Phosphor icon in its state's colour, alone for what asks the person to look, with the elapsed time to the second ("38s", "1m 34s", "1h 2m"; muted ink, tabular figures) for work under way. The set (`components/status-icons.tsx`, the only place it is defined): needs a model `SlidersHorizontal` fill, approval (and any other request: review, Not sent) `HandPalm` fill, question `Question` fill (all three `--row-status-needs-you`); failed `WarningCircle` fill (`--row-status-failed`); working `CircleDashed` bold (`--row-status-working`), still; waiting on agents a dashed circle of the same look holding the count in bold tabular figures, 1–9, or a small dot above 9 (`WaitingCountMark`, `--row-status-waiting`), any other wait (the queue, a recovery) `ClockCountdown` fill in the same colour; held at a usage limit `Gauge` fill in the muted ink (monochrome), with no time (the tooltip says when it lifts); background work only `TerminalWindow` fill (`--row-status-background`); finished, not yet seen `CheckCircle` fill (`--row-status-finished`). A seen failure is the warning circle in muted ink beside its age; done-and-seen and idle rows show their age alone. The colours, one per state and the same in every theme of a scheme (dark / light): needs you #EDB250 / #AD7200, failed #F47670 / #C93A33, working #7E9FD6 / #3D63A6, waiting on agents #A08FD4 / #6A55A8, background #7E8692 / #6B7380, finished #6CBF8C / #2E7D4F; softened so they read without shouting; each holds 3:1 on the sidebar, its hover and the open row (theme/readability.test.ts). The state's meaning ("Needs approval", "Has a question", "Needs a model", "Failed", "Waiting on 3 agents", "Finished", "Done") is the status's tooltip and accessible name, and leads the row's accessible name after the title. Line 2: the title, `text-md`, semibold only while the thread needs the person, regular otherwise. Line 3 (`text-meta` subtle, always 16px tall, its marks at the right even with no branch): the branch (mono, middle-truncated) · the PR glyph and number in the same muted ink … another machine's mark only when the thread runs on another machine (none for this one), and the provider's mark in its own colours at 80% (a single-colour mark in the foreground ink at 80%), never with an account bubble (the hover card names the account). A pinned row adds a small pin glyph (11px, subtle) after the project's name. A snoozed row says what it waits for where the status sits, with a small clock ("until it needs you", "until the PR changes", "until Mon 9:00 AM"), unless it needs the person. A settled row's title is in the muted ink. Open thread: `--active` fill, no bar; hover: `--hover`. Under the pointer or focus the row's actions (Snooze, Settle or Unsettle, ⋯) sit on line 1 beside the status, which stays. The hover card's first line under the title says what the thread waits on in words (`hoverStatusLine`): "Waiting for approval", "Has a question", "Choose a model to start", "Failed" (with its reason when the status has one), "Working" (with its step when known), "Waiting on 2 agents", "Running in background" (its command in mono), "Finished"; nothing at rest. The row's own icon leads the line in its state's colour; the words are amber for what needs the person, red for a fresh failure, muted otherwise.
- **List row (chats):** chats are one line of `--row-height` (36), `text-md` (14) 400 in foreground ink (600 while it needs the person), 10px side padding, 10px between glyph and text, `rounded-md`, inset 8px from the sidebar edge, 2px between rows, no dividers. The right edge carries **at most one** mark, from the row's attention (`rowIndicator`, `rowStatusLook`): the thread row's 16px status icon in its state's colour, for a request, a fresh failure, unseen finished work, or work that still runs or waits. Still, never animated. A thread that needs the person has a semibold title. Nothing at rest. No status words, spinners, branches, pull requests, provider glyphs, subagent counts or machine marks: they live in the thread, the row's spoken name and its hover card (which also shows the browsing and computer-use marks). Open thread: `--active` fill, no bar; hover: `--hover`, and the row's actions take the mark's place. A settled chat is the same line with its title in subtle ink and no mark.
- **Threads tabs:** Inbox, Snoozed and Settled are text tabs under the title row, 28px, `text-meta` 500, 10px side padding, `rounded-md`; the open one on the `--active` fill in foreground ink, the others subtle, foreground on hover. Inbox and Snoozed carry a quiet count after the word (`text-xs` 400 subtle; none at zero); Settled has none. No icons, underlines or pills. Section labels (`panelLabel`: 28px, `text-ui` (13) `--muted-foreground`, 20px above) are the Chats panel's; the Threads panel has none.
- **Panel rows** (every place: Skills, Automations, Settings, Code review): the list row's line (`panelRow`, `--row-height`, `text-md`, a 16px muted glyph or 16px of room, `rounded-md`), `--hover` under the pointer and the `--active` fill for the current one. A row's own facts trail it on the same line in `text-meta` muted (an automation's status word and when it runs, a skill's provider marks or Off). Section labels are the panel's (`panelLabel`); a group that folds (a skill's home) is the same label with a caret.
- **Full pages (pull requests, issues, their lists, History):** a page's title is the top bar's; a Code review list page carries no Inbox / Pull requests / Issues switch, since Code review's panel is the way between them, only its search, its filters and its one action. One gutter for every band (`--forge-gutter`: 16px in a narrow column, 32px beside it). Titles, bylines, merge gates, tab bars, section headings and rows all start and end on it. Anything drawn as a box (icon buttons, row hover washes, word tabs) overhangs it, so its text or glyph lands on the edge rather than its box. Back hangs in the gutter left of the title. Bands above a scroller keep the scroller's track space (`scrollbar-gutter: stable`) so right edges agree.
- **Side panel:** a 44px strip (tabs, +, the tab list, the showing tab's actions, a `controlDivider`, full view) and an opaque body; sections separated by `sectionRule`; `rowCard` for outlined list rows. Nothing else is drawn. Docked beside the column or in full view, the strip is the top bar's part above the panel (no `toolbarEdge`: the canvas's top hairline is the line, with one hairline where the panel meets the column) and ends with the panel's toggle; its empty space drags the window, its tabs and buttons don't. Docked at the bottom, the strip heads the panel itself with `toolbarEdge` under it. The panel always docks: never a floating overlay, sheet, modal or scrim. On a phone-sized window it takes the canvas in the column's place, its strip the whole bar, led by "‹ Chat" (Back to chat) where full view's way back sits; full view and the toggle are left out there.
- **Layout breakpoints** (`lib/breakpoints.ts`, `lib/shell-room.ts`): above 896px the sidebar sits beside the content, at and below it a sheet. From 640px up the side panel docks beside the column, and the width is shared in one order (`allocateRoom`): the sidebar steps aside first (at 1100px and below while the panel is open, or wherever it would leave the column and panel less than their minimums; the person's own choice comes back when the panel closes); then the panel narrows towards 320px; the column keeps 360px, and below that the panel caps its width rather than covering it. Widths follow the window continuously, and a dragged width is kept and drawn again once there is room. Below 640px the panel takes the column's place. Docked at the bottom, the panel is a split under the column at every width.
- **Summary (side panel):** top to bottom, each part only when it has something: **Now**, one short line in `text-md` 500 (who needs the person and for what, "Working · 35m", "Done · 52m", "Failed", the time muted) with the model quiet at its right, then one grey line (what works, what came of it, or the ask with an **Open** text link to the asking agent); active work; **Since you looked**, 2–4 plain bullet lines with a quiet **Clear**; **Agents** with their count, the whole tree across delegated threads (ADR 0108); **Results** (pull requests, files changed by which agents with **Review**, checks in words; closed pull requests fold into one quiet line); **Plan**, "N of M", a 3px line and the checklist; the project's automations as one quiet line at the foot. Sections part by space under a small grey heading: no cards, no rules, no stats strip.
  - **Tree rows:** 30px, caret (when it has children), provider mark, name (500), what it is doing in grey, time at the right (it gives way to Stop on hover). Each level steps in 18px and hangs on a 1px `--border` guide under its parent's mark. Background commands are `$ command` rows under the agent that started them. A live branch is open; a settled one folds to one line saying what it holds ("opened #1542 · 1 done"); the person's folds are kept per thread.
  - **Status without glyphs:** the provider mark is the row's only status mark: foreground and breathing (opacity and scale, 2.4s, `.fx-alive`) while it or anything under it works or waits, still at rest, 55% when done; still under reduced motion and while facts are stale ("last seen …"). Colour is only words: the warning colour for a request, `--destructive`-tone for a failure. Everything else is greys.
- **Dialog:** `rounded-card`, 20px padding, solid, 480px (confirmations) or 640px, title `text-lg` 600, body `text-ui` muted, footer right-aligned: Cancel then the action. Danger confirmations: solid red action, focus starts on Cancel.
- **Popover / menu:** `rounded-popup`, 4px padding, 30px rows `rounded-md` (concentric), 16px icon muted, label `text-ui`, shortcut `text-xs` subtle right-aligned; `--border` separators with 6px margins; destructive rows in `--destructive`.
- **Toast:** top-right of the content column, just under the header, 320px, plain `glass-thin`. A small glyph in the kind's colour before the title (error red, warning amber, success green, info blue; a spinner for progress; none for a plain confirmation), the description muted below with Show more past two lines, the one action as a small primary button at the bottom right, and Dismiss as a small round button on the card's top-right corner. Never over the header, never over a side panel.
- **Empty state:** `EmptyState` centred: faint icon, title (`text-base` 500), one muted line, one secondary action. Never a bare sentence at the top of a page. Before a query, search and the palette offer recents and commands, not prose.
- **Error state:** the same anatomy with the failed glyph; the line says what happened and what to do, in that order.
- **Context handoff divider:** the transcript's one centred row, where a thread moves to another provider. Two `--border` hairlines run to the column edges around one `text-meta` muted line: the Phosphor arrows-left-right glyph, "Context handoff" (500), each source model's provider mark (in its brand colours) and name, comma-separated, at most three then "+N", an arrow, then the new model's mark and name in `--foreground`. It is static: nothing opens from it. Every other system event stays a left-aligned `SystemRow`.
- **User message bubble:** right-aligned, `--bubble`, `rounded-lg`, at most 80% of the column, at the answers' reading size. Markdown the writer meant (a fence, a heading, a list of two or more items, a quote, a table, a link, inline code, emphasis around words) renders with the answers' markit renderer and styles, raw HTML shown as text; anything else is plain text exactly as typed, line breaks kept. Rendered markdown keeps every typed line break too. Nothing is wider than the bubble: words, URLs and paths wrap anywhere, inline code wraps, code blocks and tables scroll sideways inside it, images fit. A long message folds under "Show more" / "Show less", rendered markdown by its drawn height, fading the last line. Copy copies the text as written; Edit edits it.
- **Sent from another thread:** a message another thread's agent sent this one (a delegated task, a `thread_start` brief, a follow-up through `agent_message`, work from an agent on a paired machine) is the person's right-aligned bubble, the same component, never a card. Above it, in the eyebrow's place, one `text-xs` line: the sender's provider mark (12px, its usual tone), then "Sent by <the sending thread's title>", its current title where this machine lists it, with " · Arpan's MacBook Pro" when the sender is on another machine. A long title ends in an ellipsis; the tooltip holds the whole line. Without a title it reads "Sent from another thread". At rest the line is `--muted-foreground`; under the pointer or keyboard focus the whole line brightens to `--foreground` over 120ms, with a pointer cursor and no underline, fill or pill. It is a link that opens the sending thread (on its machine, through the paired-machine view, while that machine is reachable). An unknown sender or an unreachable machine leaves it plain text that never brightens. The bubble shows the words without ace's frame ("Role: …" / "Task:"), folded to four lines past five (`sentFold`) with "Show more ⌄" / "Show less" at its foot. Handoffs and automations keep their own labels.
- **Loading:** skeleton pills (`--skel`) in the value slots at the control's size; labels and headers render as normal. Spinner rings (still, like every live mark) only for live work (the working glyph, Send → Stop), never as a page's loading state. The boot splash is the only full-page loading mark.

## 5. State and attention

- **Attention levels** (`rowAttention`): _needs-you_ is always strong (status colour, 500). _failed_ is strong until seen, then a quiet word. _working_, _waiting_ and _background_ are muted unless open, but always keep their elapsed time beside the word; the open row takes its colour. _done-read_ is muted with only a relative time. The open thread reads at full contrast.
- **Colour means state.** Working blue, needs-you amber, failed red, done green, waiting violet, unresponsive pink. Never reuse these for anything else; never show a status by colour alone.
- **Focus:** `focus-ring` (2px gap, 2px `--focus`) on controls; `focus-ring-inset` on rows inside scrollers; on glass the ring is the full-strength ink. A dialog's auto-focused Cancel shows a hairline until a key is pressed. Programmatic focus targets show no ring.
- **Hover:** `--hover` wash, text one tier stronger. **Press:** `--active` wash, `scale(0.98)` (not under reduced motion), shadows removed. **Open/expanded:** `aria-expanded` takes the `--active` wash.
- **Disabled:** 40–50% opacity, no pointer events, and a `reason` tooltip when the user could fix it.
- **Rail signal:** while a thread needs the person and they are in another place, Threads in the rail shows an 8px needs-you dot on its top-right corner, its name and tooltip saying how many. On Threads, none: the list says it. Code review carries the same dot while pull requests wait on the person, else a blue dot while notifications are unread.
- **Selection:** `--active` fill on the row's rounded box for lists; the primary fill for checked controls; `::selection` is the accent at 32%.

## 6. Copy

- Plain, direct, present tense. Say what happened, then what to do. No exclamation marks.
- **Sentence case** everywhere, including view names: "Back to home", "Go to activity". Product names keep their case.
- **Buttons are verbs** that name the outcome: "Allow once", "Stop and delete", "Pair a device". Never "OK", "Yes", "Submit".
- Status words are the vocabulary in `@ace/ui-core`: Approve, Answer, Working, Failed, Done, Waiting. Don't invent synonyms.
- **Errors** name the thing and the cause in one line and offer the next step: "Couldn't copy the link. Clipboard access is blocked in this browser." No codes in the first line; Details holds them.
- **Nothing narrates the UI**: no "Beginning of thread", no hint prose under controls, no "Tip:" rows, no always-visible explanations of what a button does. Explanation goes in a section note, once, or in a tooltip.
- Numbers use tabular figures; times are relative in lists ("9m", "2h", "Mon") and absolute in detail views.

## 7. Accessibility

- Text ≥ 4.5:1 on every surface it sits on (`--foreground`, `--muted-foreground`, status words); tertiary hints and icons ≥ 3:1. The theme tests enforce this for every theme × scheme × accent, and the glass solver enforces it over blurred backdrops. Contrast settings may not drop below these floors.
- Hit targets: 30px on fine pointers; 44px on coarse pointers via `touch-hit` (never by growing the control). Rows ≥ 32px.
- Keyboard: everything reachable in DOM order; lists use arrow keys and `data-row-focus`; menus trap focus; `Escape` closes the top layer only. Focus returns to the control that opened a layer.
- Reduced motion (`[data-reduce-motion]`): fades stay, distances and scaling go to zero, `.fx-flourish` stops; live marks are still anyway, and an indeterminate progress bar breathes in place instead of sweeping.
- Reduced transparency (`prefers-reduced-transparency`) and the Solid setting: `data-surface="solid"`, no backdrop filter anywhere; the same edge and shadow carry elevation.
- Every icon-only control has an `aria-label`; every status has a word for assistive tech, never a colour alone.

## 8. Owner decisions (binding)

- **Clean, T3-like UI:** every element shows state the user acts on; nothing narrates the UI to itself.
- **Sidebar shell:** a rail of places beside the current place's panel (ADR 0107); the rail is always there, with no Back to app mode. Spade shows in the rail as coming soon until it launches.
- **Sidebar (Threads panel): Inbox, Snoozed, Settled.** The owner chose this on 2026-11-01 (ADR 0107), replacing Active on top with settled threads in their projects. Top to bottom: "Threads", the Everywhere filter, Search (the palette) and New thread; the tabs; then the open tab's list.
  - **Inbox** is one flat list of every unsettled, unsnoozed thread across projects and machines, in the order the person would act: pinned (in the person's order), then what needs them (a request: approval, question, plan; or a failure not yet seen), then what runs (the thread or its agent tree works or waits, or a background command runs), then finished work not yet opened, then the rest; each band by most recent activity. There are no headings: each row's status word says why it is where it is. Newest first and Manual (Sort threads) keep their own order below the pinned ones. Unsent drafts sit on top. Membership is the daemon's settle and snooze facts read through the row's attention (§5): a thread whose agent tree still works or asks is in the Inbox even when it was settled, and a snoozed thread that needs the person is in the Inbox too.
  - **Snoozed** lists snoozed threads, the soonest to wake first, each saying what it waits for. **Settled** lists settled threads at rest, newest first, in muted titles; it pages in as it scrolls (up to 100), then its last line says older settled threads are in search (⌘K).
  - **Filter:** projects and devices are a filter, not the structure. "Everywhere ▾" opens the project and device filter; it narrows all three tabs, and its button then names the project or device.
  - **Snooze** offers, besides 1 hour, Tomorrow and Next Monday, **Until it needs you** (only while the thread works or waits: it returns the moment its tree asks for an approval or an answer, fails or finishes) and **Until the PR changes** (only with a linked pull request: a new review or comment, a push, or checks finishing). Settle and snooze confirm in a toast with Undo (⌘Z too).
  - **Keyboard** in the panel: J/K (and ↑↓) move, E settles the focused row (focus moves on), H opens its snooze menu, 1/2/3 open Inbox, Snoozed and Settled.
  - **Empty:** "No threads yet" while there is none at all; "Inbox zero" ("Nothing needs you, and nothing is running."), "Nothing snoozed" and "Nothing settled" otherwise, with " in <project>" or " on <device>" and Show everywhere or Show all devices while a filter is on.
  - **History** stays a full main-column page (`/history`, `?project=`), reached from the palette and its route; the panel has no way to it of its own.
  - **Search** is the palette's (⌘K, or Search in the title row), settled threads included.
- **Chats panel (2026-11-01; ADR 0107, ADR 0099).** Chats, threads started with no project, have their own place under Threads, and the Threads panel and History leave them out. The panel reads as Threads does: Active on top, every unsettled chat (pinned first, then what needs the person, then what is at work, then the rest by last activity), then the settled chats under Today, Yesterday, Previous 7 days and Earlier by last activity, dimmed (section labels, `panelLabel`), each row the list row of §3 with its one mark and hover card; hover or focus puts Rename, Pin, Move to project and Delete in the mark's place. A settled chat whose agent tree still works or waits is Active, never dimmed. Settled chats have no History. "Search chats" narrows titles as the person types and finds older chats through the daemon's search; Esc clears it. Older chats page in as the list nears its end. Empty, it reads "No chats yet" with New chat, which starts a chat at once without asking for a project. Chats from every connected machine are listed (ADR 0102), each acting on its own machine and naming it, as Threads rows do, in its spoken name and hover card, never on the line. The device filter is the Chats panel's own, apart from Threads': it narrows the list, the search and the paging, and a device with none reads "No chats on <device>" with "Show all devices". New chat starts on the chosen device (else this machine), with New thread's "on <device>" line to move it. While a chat is open the top bar shows a chat bubble before its title, not a folder. The Chats title row carries only its title and New chat.
- **Attention levels:** as in §5.
- **Composer:** nothing renders below it; exactly one strip slot above it (approval/question first), tucked under the composer's edge; Send and Stop are round; live state is the inline "Working for …" line at the top of the live turn, under its ask; finished turns fold into "Worked for …" disclosures in that same place. While the main agent does nothing itself (it waits on its subagents, or its turn ended or was stopped and background commands it started still run) the inline line steps aside: the strip says "Waiting for 2 subagents · …" (with "· 1 command running" when commands run beside them), or, with only commands left, "Running 2 commands" or "Running `bun run dev`" (only a shell's command is code), with no glyph and its Stop at the right edge. A stopped turn already reads stopped in the transcript, so the strip never repeats "Stopped". ace's own bookkeeping is never counted or named there. The send slot reads Send and a message goes in now rather than queueing (the model itself isn't busy); the thread's row says Waiting while subagents run, and Background, never Working or Done, while only commands do.
- **Themes:** Mode (Light/Dark/System) is separate from Theme; themes are **colour only** (no fonts, material or spacing) and the set is ace (default), Paper, Midnight, Grove, Harbor, Dusk, with status colours the same in every theme; the accent picker stays; floating layers are glass and the composer is translucent glass; motion is 120/200/320 with the spring `linear()` curve. Mode keeps its three preview cards.
- **Depth:** the composer and its strip carry only their lift shadows (`--depth-dock`, `--depth-strip`); buttons are flat with no depth.
- **Danger confirmations:** solid red button, focus starting on Cancel.
- **Unified frame (2026-10-31):** one top bar across the window and the rail on the frame colour; the sidebar panel, main column and side panel share one canvas on the page surface, starting with a rounded corner at the panel (§3, Shell; ADR 0107; owner, 2026-11-01).
- **Header order:** `[back] [forward] [sidebar toggle]` after the traffic lights, then `[folder glyph] [title] … [⋯] [Work icon] [panel toggle]`; Work info is a compact floating card.
- **Model control:** one composer control (model chip + speed icon + effort label) with a T3-style list popover.
- **Real icons only:** provider marks, Phosphor, favicons. No emoji.

## 9. Review checklist

Answer every one with yes before approving a UI PR.

1. Does every new element show state the user can act on, with no narrating or hint prose?
2. Are all colours tokens, with status hues used only for status?
3. Do text tiers follow §2 (title 500, secondary muted, tertiary subtle, icons faint)?
4. Are rows, controls and insets on the grid at the token heights, with no 14px literals?
5. Are radii from the scale, no larger than the padding beside them, sized to the element, and concentric when nested (§2 Radius)?
6. Do separators come from `rules.ts`, with nothing in the sidebar ruled?
7. Is depth only from `--depth-*`, on the composer/strip and the remaining depth controls (never buttons), never on content? Is every floating layer `.ace-floating`, `.ace-glass-dock` or `.ace-floating-solid`, with no glass on glass or on a scroller?
8. Do primary/secondary/ghost/danger follow §4, with one primary per surface and danger only on the confirming action?
9. Does the page title row carry at most one action, and do add actions sit inside cards?
10. Do empty, error and loading states use `EmptyState` and `--skel` as in §3?
11. Are tabs `SegmentedControl`, `Tabs` or `WordChoice`, never a fourth style, all flat (no shadow) with the selection shown by a fill?
12. Does every animation use `--motion-*` and `--ease-*`, animate only transform/opacity, and respect `[data-reduce-motion]`?
13. Is focus visible on every interactive element, and does focus return to the opener when a layer closes?
14. Are hit targets 30px fine / 44px coarse, and does every icon-only control have an `aria-label`?
15. Is copy in sentence case with verb buttons, and do errors say what happened and what to do?
16. Were the 390, 768, 1440 and 1920 widths checked in light and dark, with screenshots in the PR?
17. Does `bun run check` pass, including `check:ui` and the theme contrast tests?
