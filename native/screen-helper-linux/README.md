# Linux screen helper

Rust helper for protocol v2, with v1 command compatibility. One process owns capture, input, a bounded AT-SPI ref cache and the private binary frame connection. No action invokes an executable. The daemon keeps the helper alive through stop/start and target inspection. One active capture is allowed per host helper.

## Build and install

On Debian, install a Rust toolchain plus `build-essential libpipewire-0.3-dev libspa-0.2-dev`. Run `./build.sh` on x86_64 or aarch64 Linux. It requests static CRT linkage and produces one ELF executable. PipeWire is loaded from the session's installed `libpipewire-0.3.so.0`; its SPA modules and compatible glibc must be installed for Wayland. X11, D-Bus, JPEG and Rust dependencies live in the binary. This is not a self-contained Wayland runtime: the compositor's PipeWire installation remains a dependency. Do not claim portability to musl-only systems.

Install the release binary once at `DATA/helpers/screen-linux/x64/ace-screen-helper-linux` or `DATA/helpers/screen-linux/arm64/ace-screen-helper-linux`. Do not rebuild or overwrite it during daemon startup. `installedLinuxHelper()` resolves that stable path; `ACE_SCREEN_HELPER` can point at an explicitly installed development binary. Run `cargo test` for portable policy/protocol/token tests and `cargo check --target x86_64-unknown-linux-gnu` for Linux Rust code. macOS cross-checking does not link the C ABI shell; release linking occurs in Linux.

Launch with `--endpoint unix:/private/directory/frames.sock --backend x11|wayland`. The daemon creates the directory with mode 0700 and socket with mode 0600; the helper rejects a non-private endpoint or another owner's socket. `--socket PATH` remains a v1 alias. Stdin/stdout carry newline JSON, at most 64 KiB per command/reply. `hello` negotiates capabilities. `start` supplies a session id, target, allowlist and fps 1..30. Only independently decodable JPEG is currently negotiated. Packet headers include v2 `seq`, `ts`, `scale`, dimensions, codec and payload length, plus v1 session/sequence/timestamp aliases for existing recordings. Stop releases XDamage/XShm or the portal/PipeWire session; capture currently requires an explicit stop when viewers leave; stdin EOF shuts down the process.

## Linux session behavior

Wayland wins when both `WAYLAND_DISPLAY` and `DISPLAY` are present, preventing accidental XWayland control of a native Wayland application. Explicit `ACE_SCREEN_BACKEND` overrides selection only when that display exists. No session produces a headless error, rather than an empty successful screenshot.

X11 identities are EWMH `_NET_WM_PID` plus exact `WM_CLASS`, exposed as `bundleId` for compatibility with the existing approval UI. Capture resolves the approved window independently. All input rechecks process identity, active window and bounds. X11 is intrinsically a shared trust domain: a malicious X client can forge properties and snoop other clients. Whole-display capture is disabled because this backend cannot enforce ADR 0011's application filtering. App targeting requires exactly one matching window; otherwise select a window explicitly. Capture blocks on XDamage and the stop pipe with no idle timer, coalesces damage at the fps cap, and suppresses redraws of identical pixels. Geometry is capped at 16 megapixels; output is capped at 3840x2160. Downscaling uses server-side XRender before XShm readback and JPEG. Xvfb executes that pipeline in software; accelerated X servers can use their GPU.

Wayland uses one combined RemoteDesktop/ScreenCast session. The chooser controls the source and may prompt on first use, after revocation, or when the prior source disappears. Pass `--restore-token DATA/screen-artifacts/portal/restore-token`. Mode-0600 tokens are atomically replaced after every successful start. RemoteDesktop v2 or newer can persist consent; older backends are reported as nonpersistent. ScreenCast source bits report whether a backend supports windows and displays; granted device bits determine input support. GNOME and KDE differ by installed portal version, so the helper reports version, desktop, restoration and source/device support instead of promising identical behavior. Idle PipeWire frames are compared before encoding, and no unchanged frame is emitted. The PipeWire loop blocks on session events and a stop pipe without a periodic wakeup.

Portals do not expose an EWMH window id or authenticate a source's application identity. Capture ids are therefore chooser hints, never claims of enforced target identity. AT-SPI on Wayland independently scopes to the exact approved executable basename, with one accessible application and one accessible window. This scope is reported in portal capabilities and can differ from the source the human selects. Multiple windows return a typed unsupported/ambiguous error; native semantic actions remain scoped to the approved application. Pointer fallback is disabled when the source cannot be mapped safely to the semantic element. Display capture is view-only.

AT-SPI refs use D-Bus unique names plus object paths. Cache size is 4096 refs with FIFO eviction; each action reads fresh properties. Traversal has depth 32, node 512, response 60 KiB and command deadline caps, and uses indexed children rather than fetching an unbounded subtree. `ui.find` visits at most 512 nodes and returns at most 128 results. `setValue` uses EditableText; `text.type` inserts Unicode at the focused editable element's caret without key simulation. Applications that expose no EditableText return `not_supported`. Password values are omitted. Unsupported press/focus can fall back to the element's center on X11 and explicitly report `fallback: true`; unsupported actions without a safe pointer equivalent fail.

## Integration and performance

For this revision, tests, Docker integration, mutation runs and benchmarks are **not executed (tests run at merge)** by repository-owner instruction. All runtime behavior and performance numbers need a run at merge. Static `cargo check` on macOS validates Rust but does not compile or link the PipeWire C shell. The commands below describe the merge-time verification paths.

Run `./test-in-docker.sh` from macOS or Linux with a working Docker engine. `ACE_TEST_PLATFORM=linux/arm64` exercises native aarch64; default is linux/amd64. A Debian container starts Xvfb, Openbox, the accessibility bus and a GTK app. It checks actual JPEG decoding, changed pixels after XDamage, XTest clicks/keys, Unicode insertion, tree pruning, stable refs, find, semantic actions, target approvals and bounds errors. The script uses unique names and removes only its own container/image in `finally`, including on failure. It never prunes unrelated Docker resources. Build cache layers can remain until Docker evicts them.

The harness also prints non-gating idle/changing CPU, observed fps, large-tree latency and RSS. `cargo run --release --example encode` measures JPEG latency. `bench/session.py` samples real Linux CPU ticks while draining frames. Timing does not determine test success. Container numbers reflect the container/VM CPU and must be labeled as such in a PR.

## Manual Wayland plan

Test on both a current GNOME session and a current KDE Plasma session, as the same local user running the daemon:

1. Check `hello` against portal version and AvailableSourceTypes/AvailableDeviceTypes. Check window support, persistence and missing AT-SPI behavior, including a compositor with capture but no RemoteDesktop portal.
2. Start a window capture. Approve the chooser once. Verify JPEG dimensions, pointer motion/click/drag, named keys/modifiers and scrolling at 100%, 150% and 200% display scale. Select a display separately and verify input is refused.
3. Stop, then start in the same process. Restart the helper with the saved token. Verify token rotation, no prompt where persistence was granted, and another prompt where the backend cannot persist.
4. Revoke portal consent in desktop settings. Cancel a chooser, close its source, unplug a display, and terminate PipeWire. Verify typed failure, no stale screenshot, and that restart never silently restores agent control.
5. Inspect a single-window GTK and Qt application with an approved executable identity. Compare tree names, text, bounds and truncation, find a control, change Unicode text, and invoke a button through AT-SPI. Test ambiguous multi-window scope and stale refs. Confirm no action reaches an unapproved executable.
6. Leave the target unchanged, then animate it at 10 fps. Run session benchmarks and report CPU/RSS/latencies. Disconnect all viewers and explicitly stop the session; confirm the portal/PipeWire session closes while the helper identity remains stable.

macOS and Windows release packaging must retain stable identities as well: macOS Developer ID, hardened runtime and notarization of an `.app` with Info.plist and stable bundle id; Windows Authenticode. Development signing must use a stable identity. This Linux task does not change the existing Swift v1 implementation or supply Windows UI Automation.
