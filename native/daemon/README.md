# The daemon's Rust core

The event store first ([ADR 0222](../../docs/adr/0222-the-event-store-moves-to-rust-behind-the-same-store.md)),
then the engine and adapters, agent-control and machines, each a crate here.

- `crates/ace-store`: the store as a Rust API. Today, the SQLite connection
  (`src/sqlite.rs`, the crate's only unsafe code) that every daemon connection runs on with
  `ACE_STORE=native`.
- `crates/ace-daemon-node`: the N-API addon the daemon loads; it only translates values,
  errors and handles. Its TypeScript side is `packages/provider-kit/src/native-sqlite.ts`.
- `crates/ace-protocol`: the `@ace/protocol` values the engine reads and writes as Rust
  types, generated by `scripts/generate-rust-protocol.ts` via `typify` (committed,
  never hand-edited); `bun run check:daemon-native` regenerates and fails on a diff.
- `crates/ace-protocol-gen`: the generation-time only helper the script above runs.
- `crates/ace-core`: the fact reducer (E4 owns the port).
- `crates/ace-core-wasm`: the same reducer for `fake-daemon` in the browser, built by
  `scripts/build-core-wasm.ts`.
- `crates/ace-adapter-api`: the adapter interface as Rust traits and errors, with the byte
  helpers every adapter needs (`util/`, ported with their cases).
- `crates/ace-supervisor`: process supervision behind `@ace/provider-kit`'s exports
  (E2 owns the port).
- `crates/ace-adapter-{codex,claude,cursor,opencode,acp,pi}`: one crate per provider, so
  builders work in parallel; translators land in `translate/` (E1), sessions in `session/`
  (E3).
- `crates/ace-engine`: the engine on the native core (E5 owns the port).

Build: `cargo build --release -p ace-daemon-node` (the daemon loads
`target/release/libace_daemon_node.{dylib,so}` or `ace_daemon_node.dll`, or the file named by
`ACE_STORE_ADDON`). Checks: `bun run check:daemon-native`. Proof: the store's TypeScript tests
with `ACE_STORE=native` (docs/store/behaviour.md §15).
