# Provider discovery and sign-in status

`providers.request` with `operation: "list"` returns the daemon's in-memory cache immediately. `operation: "refresh"` awaits one shared refresh. List requires read scope; refresh requires operate scope. `providers.result` contains installation and native authentication observations, independently of adapter availability and ace account registration. Generic ACP installations remain in `registry.list`.

The daemon starts refresh in the background, repeats it five minutes after completion, and cancels probes on shutdown. Every CLI probe has a four-second deadline and bounded output. Concurrent refreshes share the same work. No refresh sends a prompt or starts an agent session. The daemon stores no discovery output in SQLite or on disk. It publishes only installation metadata, recognized auth state, supported auth method labels, and validated email labels from native status output. Keys, tokens, raw output and raw exceptions never enter this wire service.

`installed: null` means discovery has not established installation yet. `installed: false` means executable resolution found no CLI. `auth: "unknown"` is distinct from logged out. `checkedAt`, `stale`, and `refreshing` let clients show pending and old observations without inventing login state. A new observation replaces old labels and paths, including after logout or uninstall. Successful native status is evidence of the CLI's reported login, not a quota or entitlement check. Account-specific runtime homes continue to use `accounts.status`.

These probes follow [ADR 0002](../adr/0002-local-cli-providers.md) and the repository's [provider research](../research/providers/README.md). Primary interfaces are documented in the [Claude CLI reference](https://code.claude.com/docs/en/cli-reference), [Pi auth check interface](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/src/cli/auth-check.ts), [Pi non-refreshing auth arguments](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/src/cli/auth-command.ts), [Pi settings](https://github.com/earendil-works/pi/blob/v0.85.1/packages/coding-agent/src/core/settings-manager.ts), and [Cursor SDK](https://cursor.com/docs/sdk/typescript). Versioned local discovery recordings in `packages/provider-kit/src/discovery/__fixtures__` establish the other CLI output forms.

The fake daemon exposes `services.providerStatuses` independently of `services.accounts` and `services.installed`. Fixtures can set explicit installed, logged-out, logged-in, unknown and stale states. Fake list and refresh use the same wire response as the daemon.
