# Working on a pull request

The repository PR list, PR workspace and linked-PR menu offer **Work on PR**. A new task opens the normal project and provider composer with a PR description. Its environment shows the selected PR head and requires an isolated worktree. The PR workspace also lets the person select an existing task in that project. Agents, background tasks and terminals must stop before the task switches checkouts.

The daemon reads GitHub metadata through the person's installed, authenticated `gh`. It matches a configured Git remote to the PR's base repository, checks the source branch, and fetches `refs/pull/<number>/head` through `@ace/git` into a private ref. This supports fork PRs without checking out the person's root or changing its index, branches or dirty files. Fetches have a deadline, accept cancellation and never fall back to a cached PR head.

Preparation pins the selected SHA and creates an owned worktree without discovering or running repository setup scripts, Makefile targets or other setup commands. PR preparation uses `GitService.nonExecuting` to guard every nested local Git call, including temporary-index reconstruction, status, checkout, verification and owned cleanup. It overrides repository, worktree, global and system hook/fsmonitor settings and disables every configured clean, smudge and process filter driver. LFS files remain raw pointer blobs; preparation never starts an LFS filter. Global attribute files and untracked-cache updates are disabled. Filter inspection reads driver names only and fails closed on invalid or excessive configuration; protected operations set GIT_NO_LAZY_FETCH and deny every transport with protocol.allow=never, including inherited child fetches. Missing objects fail with an `objects_not_available` error. The explicit PR-ref fetch uses a separate transport path in the unprotected project checkout, with hooks and fsmonitor disabled, no filter and refetch enabled so partial-clone blobs arrive before checkout. It retains the user's existing Git authentication configuration. Protected checkout roots never admit explicit fetches.

The creation journal records this policy before checkout and retains protected roots after admission, including previous PR checkouts kept during later workspace switches. Restart loads those roots before cleanup or further Git operations. All subsequent Git calls within a protected tree, including descendant directories, inherit the same policy. Removed owned trees release their protection; admitted or edited trees retain it. Preparation rechecks the hosted head/base and local HEAD before admission. This flow offers no setup execution approval; any future setup option must bind explicit approval to the verified head SHA and exact commands and execute only after final verification. Deleted or inaccessible source branches and changed heads fail visibly. PR preparation offers cancellation and retry, with no fallback to a local checkout. An existing task retains its previous checkout, including its edits.

The thread's `details.pullRequestWorkspace` records the verified repository, head/base SHAs, source branches and bounded review context. PR links use the existing forge link owner. The link and context commit with admission before the first provider prompt. Later workspace switches clear verified PR checkout metadata.

Existing-task preparation uses the engine's durable workspace reservation. Preparation and uncertain recovery keep the thread waiting on its queue. A failed operation leaves the previous binding and a visible progress record; a fresh Work on PR intent can recover it. Command receipts prevent reconnects from replaying a completed or uncertain operation. Repeating the same verified selection reuses the bound checkout. The creation journal owns unadmitted worktrees across restarts and never removes an admitted task's checkout. Interrupted draft progress is reconciled durably after owned cleanup, before the draft capacity check. Failed existing-task drafts whose resources are safely released no longer occupy preparation slots. Edited or uncertain orphans retain cleanup ownership and block another preparation for that task until cleanup is resolved.

This flow reads GitHub and prepares local Git resources. It does not push or perform a remote PR mutation. Merge, review, comment and CI action workflows can extend the PR workspace separately.
