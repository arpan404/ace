# 0008: Authenticated dev-server previews

Date: 2026-10-02, amended 2026-10-07. Status: accepted. Paired daemon link issuance, the encrypted relay adapter and the web/desktop preview panel are implemented; the native mobile bridge remains client work. See "Embedded previews and the host credential" for the 2026-10-07 amendment.

## Context

The orchestration research inventories t3code's desktop webview and planned gateway, Claude's desktop launch configs, and screenshot-based remote workflows. Those notes describe no authenticated host-local dev-server preview in a phone's own browser. They are feature references only; this implementation is written fresh. A screenshot cannot exercise cookies, service workers, SSE or HMR.

## Decision

`@ace/preview` owns discovery, launch supervision, HTTP forwarding and relay streams. It exposes small dependency interfaces for device authorization and the encrypted channel. It does not modify provider credentials or run agent prompts.

Use `p<port>-<generation>.<wildcard-host>` virtual hosts on one listener. Each registration has a fresh generation, so unregistering and registering invalidates prior links and cookies. Different listener ports have different web origins but share hostname cookies; that alternative does not satisfy cookie isolation. No body rewriting or JavaScript injection is needed with different hostnames. Upstream Domain attributes are removed to make application cookies host-only, and gateway cookies never reach the application.

Remote browsers need wildcard DNS directed at the daemon's LAN or Tailscale address. A bare IP or Tailscale MagicDNS node name is insufficient. The caller configures DNS and supplies a wildcard TLS certificate for HTTPS. HTTPS is required for service workers and Secure application cookies outside loopback. HTTP is an explicit development transport, with reduced transport security. Native relay clients use distinct `p<port>-<generation>.localhost` hostnames on loopback listeners. Their browser runtime must resolve `*.localhost` to loopback, with a native resolver override where needed. Ports alone would still share cookies. Browsers cannot create TCP listeners or act as a secure-channel peer, so remote browsers use LAN or Tailscale, not the relay.

## Public API and wire additions

- `createPreviewGateway` accepts listen interface, wildcard hostname, optional TLS, limits and a device authority. `register({ port })` only targets numeric loopback TCP ports. Both IPv4 and IPv6 loopback are supported through a pinned lookup and automatic family selection. `mintLink({ port, deviceToken })` authorizes a paired device before issuing a short-lived signed link. `unregister` closes in-flight work. `close` owns all connections.
- `discoverListeningPorts` uses bounded `lsof` output on Darwin and bounded `/proc/net/tcp{,6}` reads on Linux. `pollPorts` emits added/removed ports, doubles its delay while unchanged and resets after change. Discovered ports are suggestions, never automatically exposed.
- `TerminalUrlScanner` consumes bounded chunks, retains a small incomplete suffix and reports loopback HTTP(S) URLs. Terminal PR #7 can feed its output hook without a package dependency.
- `.ace/launch.json` has a bounded `configurations` array. Entries contain `name`, `command` or `runtimeExecutable`, optional `args`, `cwd`, `env`, `port`, `autoPort`, or `url`. `command` is an executable, not shell source. An attach URL is HTTP on loopback only. `autoPort` reserves a free port before launch, injects `PORT`, then releases the reservation immediately before spawning. Generic CLIs cannot inherit that listening socket; a small bind race remains and failed launch is reported. Start and stop use `@ace/provider-kit/process` to own process groups. An additive opt-in `maxLineBytes` limit kills preview launches with output lines over 64 KiB before readline can retain them; delivered lines are capped at 8 KiB. Launches do not imply forwarding permission.
- Preview control schemas are additive, in `@ace/protocol/preview`. They describe list/start/stop/forward/unforward/link requests and discovery/launch descriptors. This library does not add unauthenticated daemon endpoints. The daemon must dispatch those controls only after pairing authorization.
- `attachPreviewRelay({ channel, allowPort })` is the host endpoint. `openPreviewProxy({ channel, port })` returns a localhost URL and a close handle. A portable `@ace/preview/transport` entry injects a `PreviewLoopbackRuntime` for a future mobile native TCP/HTTP bridge; the Node entry supplies the tested loopback implementation. The Expo bridge itself is client work. Channel adapters must deliver ordered binary messages, resolve sends only once admitted under their own bounded backpressure, notify close, and provide a close method that aborts both peers. Each proxy owns an exclusive preview subchannel; the relay adapter must demultiplex it from other channel users. The host authorizes each requested port using the paired-channel identity captured by its `allowPort` callback.

Relay version 1 frames use network byte order and have a 12-byte header: version u8, kind u8, reserved u16=0, stream id u32, value u32, followed by at most 16 KiB of binary data. Kinds are OPEN (value=port), READY, DATA (value=payload bytes), CREDIT (value=consumed bytes), END (TCP half-close), RESET. Client allocates monotonically increasing nonzero ids and never reuses them in a channel. Both directions start with 256 KiB credit after READY. A receiver replenishes credit only after its destination write completes. Invalid frames, credit overflow and unknown kinds close the channel endpoint. Stream count and socket count are capped; excess opens are reset. Pending control/data sends are capped at 34 times the stream cap plus 32; overflow closes the endpoint rather than growing a blocked transport queue. Data is never JSON or base64. Reconnection creates a new endpoint and new sockets; old streams fail visibly rather than replaying HTTP writes. HMR can then open a new websocket normally.

## Security

HMAC-SHA256 links are audience-bound to the exact preview hostname, expire after 60 seconds, and consume a nonce synchronously before setting the session cookie. Outstanding nonce storage has a hard cap; expired entries leave in issuance order. Link URLs use a reserved login path, redirect to `/`, and carry no-store and no-referrer headers. The cookie is HttpOnly, SameSite=Lax, host-only, and Secure on HTTPS. HTTPS uses the __Host- prefix. Lax allows the first top-level navigation after a cross-site signed-link redirect to send the new cookie. Requests with a foreign Origin still fail. The Node client's internal loopback TCP bridge requires a fresh 32-byte capability prefix before it can open a relay stream; it is never an anonymous bypass around HTTP Host/Origin checks. Native bridge implementations must protect any internal listener too. Signed sessions expire after an hour, bind to the generation and device, and recheck device revocation on every HTTP request and websocket upgrade. Daemon preview sessions permit arbitrary application HTTP methods and websocket messages, so link issuance and subsequent requests require paired `operate` authority through the existing `allows` predicate. Read-only devices cannot obtain these mutation-capable sessions. The local host credential may mint them only over the loopback socket; see "Embedded previews and the host credential". A restart changes the signing secret and invalidates old sessions. Existing sockets require explicit `revokeDevice` when pairing is revoked.

Reject unknown Host values, foreign Origin values, absolute-form request targets, CONNECT, unauthenticated upgrades and arbitrary upstream addresses. Strip hop-by-hop and forwarded headers, rewrite Host and accepted Origin to loopback, and rewrite loopback Location redirects to the preview origin. External redirects stay external. Cookie Domain is removed; attempts to set the reserved gateway cookie are discarded. Limits bound tokens, registrations, connections, headers and relay frames. Authorization errors fail closed. Applications are still untrusted development code; a compromised dev server can control its own preview origin. Do not put previews under the ace UI's cookie domain.

## Performance

A private bounded file reader starts at 16 KiB and grows geometrically up to 4 MiB, so idle listener scans do not allocate full-size buffers. HTTP uploads, downloads, SSE and websocket bytes use Node stream backpressure end to end. Headers are small bounded metadata; response bodies are never accumulated. Lookup and dispatch are O(1) by hostname or stream id. Port snapshots cost O(current listeners), diff emits only changes, and polling backs off to 30 seconds. Terminal scanning is O(chunk bytes) with an 8 KiB suffix cap. Relay credit bounds each direction at 256 KiB per stream, with 16 KiB frames and capped connections. Shutdown destroys sockets and cancels pending work. Non-gating benchmarks cover HTTP streaming/fan-out, relay throughput and discovery scanning, reporting throughput and peak RSS.

## Validation

Tests use real HTTP, websocket and SSE servers, process groups and TCP sockets. They cover two-host cookie isolation, single-use and expired links, forged hosts/origins/cookies, revocation, streaming uploads and a 50 MiB download with bounded stream queues and less than 8 MiB retained byte-buffer growth in an isolated GC-enabled process, 200 concurrent connections, and websocket echo after upstream restart. Relay tests cover concurrent sockets, half-close, flow control, malformed frames and replacement channels after disconnect. Discovery tests guard change-only notifications and URL chunk boundaries. Launch tests verify PORT injection, attach and stopping owned processes. At least eight production mutations must make their named behaviour tests fail before PR delivery. `bun run check` is the delivery gate.

## Integration after remote-access landed

`ace start` starts a preview gateway by default on `127.0.0.1`, using an ephemeral port and `*.preview.localhost` origins. The backend startup API still accepts an explicit listener configuration. The default listener never binds LAN or Tailscale addresses, even when remote daemon access is enabled. Port discovery remains a suggestion; a trusted administrator must forward a port before it can be browsed. Paired operate authority is required for signed links over HTTP; the host credential mints only through the loopback socket (amendment below). HTTP is limited to loopback under the development transport policy above. Its existing persistent device store implements the preview authority. `POST /v1/previews/<port>/link` on the daemon listener accepts only a paired-device bearer token and returns `{ url }`; the host token-file credential is insufficient there. Only a non-revoked paired device with operate authority may browse a port registered by trusted host control. No remote port registration or process launch is granted by this endpoint. Existing remote-access revocation events cancel live preview streams and pending authentication, and daemon shutdown closes its owned preview listener. The existing websocket unions remain unchanged. Client UI and trusted host forwarding controls can consume the separate preview schemas.

## Integration after relay landed

`@ace/relay` now exposes additive binary send/receive methods sharing its existing Noise transport, send queue and rekey counters. Encrypted plaintext tag `2` identifies one binary record, while tags `0`/`1` retain JSON fragmentation. Preview runs on a dedicated connection after the existing hello has been authenticated and the host channel authorized. The host attaches its preview endpoint before sending a JSON switch acknowledgement; the client receives it before opening its proxy. `previewRelayChannel` then owns the sole binary reader and forwards frames without JSON or Base64. A malformed preview record closes the channel and its client loopback listeners. Forwarded-port grants and revocation remain bound to the authenticated device by the host's `allowPort` boundary.

## Review corrections

Resolve redirect references against the preview origin using the [WHATWG URL parser](https://url.spec.whatwg.org/#relative-slash-state) before matching loopback ports. This covers mixed slash/backslash authority prefixes as browsers interpret them, while ordinary relative references still resolve on the preview origin. Preserve ordinary relative redirects and external destinations. Polling owns a copy of each scanner snapshot before invoking callbacks. File reads use nonblocking open and validate the opened descriptor as regular before reading; close on every exit. Do not use the reported file size to skip reads, since proc tables report zero.

Socket close releases relay capacity immediately and cancels both credit and channel-admission waits. Graceful TCP EOF remains a separate transition that sends END only after preceding DATA. Admit at most one native chunk per paused socket, no larger than the 256 KiB window. Keep payload/frame byte counters incrementally, and expose transport queue counters through the encrypted adapter. A blocked writer retains its encoded frame, rather than the original socket chunk's backing buffer.

Regression tests exercise scheme-relative redirects through both gateway and loopback proxy, closed real TCP sockets without credit and with blocked writer admission, four simultaneous FIFO configurations, same-length wrong HMAC signatures and altered signed claims, oversized otherwise-valid DATA to a ready real TCP server, mutable scanner Sets, and cancellable supervised probes. Resource-heavy tests use correctness timeouts suitable for concurrent runs, without throughput assertions; the outer memory test aborts and reaps its child on timeout/cancellation.

Per the repository owner, review validation is static only. The regression tests, mutation cases and final benchmark results need run at merge; no test, probe or benchmark is part of this delivery gate.

The verifier follow-up declares Zod as a provider-kit test dependency and refreshes the lockfile. Native runtime regressions observe RESET and replacement HTTP success for oversized and overlapping chunks. Merge resolution retains both raw-process output caps and preview line caps, with real-process regressions for each. Preview, daemon-preview and cancellation suites join the landed process-test manifest so TLS fixtures, limited workers and integration cleanup apply. These cases need run at merge. Queue counters are conservative totals across stages, not a unique-allocation memory measurement. Terminal URL and launch output tests assert parsing and termination only; the isolated transfer test supplies retained-memory assertions.

## Embedded previews and the host credential (2026-10-07)

A live repro against a scratch daemon showed the client wiring never signed in. The panel framed the raw gateway origin and got an empty 401, so the frame stayed blank with no error. "Open outside" did the same. Nothing called the link API. The desktop app and a local web app hold only the host token-file credential, which could not mint a link, and the link route had no CORS for their origins. Even with a link, the cookie failed in a frame: the ace UI (`app://ace`, `http://localhost:<port>`) is cross-site to `*.preview.localhost`, and Chromium, Firefox and WebKit all drop a SameSite=Lax cookie set in a cross-site frame.

Decisions:

- **Links over the socket.** `preview.request` gains `{ op: "link", port }` and returns `link: { url, sessionMs }`. The daemon checks `operate` authority and thread visibility, and only mints for a port registered to that thread; another thread's port is `preview_not_found`. A paired device's session binds to its device id, so revocation still ends it on the next request. The HTTP route keeps its paired-device-only contract.
- **Host credential.** A socket authenticated by the token-file credential is host control: loopback only, never revocable, and already able to forward ports and administer the daemon. Its sessions bind to the reserved identity `host:local`. The colon keeps it apart from device UUIDs, and device tokens never resolve to it. The authority accepts it until the daemon restarts, and a restart replaces the signing secret, so those sessions end. Previewing gives that credential nothing it lacked. The desktop main process therefore needs no separate trusted path, and a local web app gets the same flow.
- **Embedded cookie.** Login sets two cookies with the same signed session. `ace_preview_session` (SameSite=Lax) serves top-level visits as before. `ace_preview_embed` is `SameSite=None; Secure; Partitioned` and serves frames. Over HTTPS both use the `__Host-` prefix. Browsers keep a Partitioned (CHIPS) cookie only under the top-level site that framed the preview. A page of another top-level site, framing or navigating to the preview, gets no session. Browsers accept Secure over http only on potentially trustworthy hosts such as `*.localhost`. On other http hosts the embedded cookie is dropped and only top-level visits sign in. The partition key is a site, not an origin, so other pages on the same site as the ace UI (other `localhost` ports) share the partition. They can frame or GET-navigate the preview, but only if they know its random 64-bit hostname, they can't read it, and Origin checks still refuse their POSTs and websockets. Lax already allowed top-level GET navigation from any site. WebKit blocks third-party cookies outright, so a framed preview there cannot sign in; the panel says so and "Open outside" still works.
- **Refusal pages.** For navigations (`Sec-Fetch-Mode: navigate`) the gateway answers its own refusals with a small page instead of an empty body: 401 `signed_out`, `session_expired` and `link_invalid`; 403 `not_previewed`; 502 `upstream_unavailable`. A fixed script, allowed by its CSP hash, posts `{ type: "ace-preview.status", status, reason }` to the parent. The message carries no credential. Other requests keep the bare status. Application responses are never rewritten. The panel accepts the message only from its own frame's window and the preview origin.
- **Renewal.** A login request that is a fetch rather than a navigation gets 204 with the cookies and no redirect. Five minutes before the hour the panel mints a fresh link and redeems it with a `no-cors`, `credentials: "include"` fetch. The new cookie lands in the frame's partition and the page keeps its state. A failed renewal retries every minute. If a session still lapses, the next refused navigation makes the panel sign in once more on its own. It does so again only after a successful renewal, so a browser that drops the cookie cannot loop.
- **Clients.** Every frame load and every "Open outside" click mints a fresh single-use link. In a browser, "Open outside" opens a blank tab, severs its opener, and navigates it once the link arrives, so pop-up blocking does not apply. The desktop CSP allows `http://*.preview.localhost:*` in `frame-src` and `connect-src`. Socket refusals now keep their codes (`forbidden`, `preview_owned_by_another_thread`, `preview_limit`, `preview_not_found`, `preview_link_refused`, `preview_unavailable`) instead of a generic `preview_refused`, and the panel explains each one.

A blank page from a working dev server stays undetectable in a cross-origin frame, because ace may not read it. The panel reports blank documents only for same-origin frames. Gateway refusals, unreachable gateways and load timeouts are reported.

Validated against a scratch daemon with Playwright Chromium, Firefox and WebKit through the real web UI. Electron 44 was checked with an `app://` page under the desktop CSP: Chromium, Firefox and Electron sign in, renew without reloading the frame, and open outside. WebKit shows the cookie-blocked error after one retry. Daemon process tests cover host-credential sign-in, renewal past the first hour, refusal pages, thread ownership, read-only refusal and revocation. Web tests cover the error states and renewal scheduling.
