# 0033: Import local provider history

Date: 2026-10-02. Status: accepted.

## Context

A new ace installation should show sessions the user already has. Codex and Claude have native session pickers and forks. Cursor lists chats across workspaces but its ACP loader cannot open TUI chats. The competitor inventories at `/tmp/ace-orch/research-t3code.md` and `/tmp/ace-orch/research-competitors.md` do not establish a complete cross-provider importer. ace needs account-aware discovery, explicit history fidelity, and native continuation without copying credentials or running prompts.

Read the provider and fixture research under `docs/research`. Recorded transport fixtures are not on-disk transcripts; tests derive native records from their message content instead of treating live notifications as history. Implementations are fresh, based on ace specs and primary provider formats.

## Decision

Add `@ace/history-import` and `@ace/native-session`. History operations run in a Node worker. A private ace SQLite index stores source fingerprints and metadata, with bounded list pages. Scan each configured instance home independently. Workspace lists show root sessions, with sidechain activity contributing to their recency. Import attaches child transcripts to the agent tree. The account boundary is `{id, provider, homeDir}`. Home selection stays host-local, and instance identity stays attached to imported threads and continuation requests.

`@ace/native-session` owns bounded JSONL iteration, head/tail sampling, Codex metadata and lineage references, and Claude sidechain paths. ADR 0018 on `feat/accounts` already owns migration planning. Until it merges, the narrow reusable contract is `CodexSessionMeta`, `ClaudeSessionMeta`, `codexParents`, `claudeSidechainRoot`, `walkFiles`, and `readHeadTail`. Accounts should replace its private metadata schema and directory convention with these exports. Migration safety, publication and writer leases remain accounts responsibilities. Do not merge the whole accounts branch into this workstream.

Discover Claude `projects/<slug>/<id>.jsonl` and `<id>/subagents/*.jsonl`, Codex `sessions` and `archived_sessions` rollouts plus `state_*.sqlite`, and OpenCode `opencode.db` or legacy `storage/session`, `storage/message`, `storage/part` JSON files. SQLite queries are read-only, bounded and schema-probed. Unknown schemas and compressed/paginated Codex histories return an unsupported reason. OpenCode v2 and SQLite scalar records above 1 MiB are unsupported. Node SQLite lacks incremental blob handles, so SQL substring would still materialize a giant cell inside SQLite. Use metadata-only `octet_length` to refuse that case before loading it; native export is the future escape hatch. JSONL oversized records remain lossless streamed blobs. Cursor is unsupported for full import: readable agent transcripts omit results, and TUI store databases cannot be resumed through ACP. No private binary decoding is guessed.

Index JSONL with at most 64 KiB at each end. A long file's message count is a sampled lower bound, explicitly labelled `sampled`; an exact count cannot be obtained from head/tail alone. Import records an exact count after a complete stable decode. Opaque oversized or malformed records keep the count sampled. Persist path, size, mtime and ctime; unchanged files incur no content reads. Sidechain changes invalidate their parent summary. Scan uses asynchronous directory iteration and fixed-size reads, with cancellation and bounded inventories. Completed scans remove stale entries; cancelled scans do not prune. Store database rows independently of rollout rows and deduplicate when listing. Reconcile removed or rebound instance IDs, homes and providers at startup, before any reads or continuation. Decode failures in small samples keep their count sampled.

Import prepares a private SQLite ancestry and result index, then reads one bounded native record at a time. Claude selects the last conversation leaf and follows `parentUuid` on disk, excluding abandoned branches. Missing ancestry fields retain sequential compatibility. Calls and results correlate by native IDs; a completion supplies status, endedAt, raw result and streamed output. Linked result notices carry `toolCallId`. Map messages, reasoning, calls, outputs and compaction to canonical items, and retain unknown records as raw notices. Historical state does not prove that a provider tree has stopped. Imported threads start `new`, and imported agents are `unresponsive` until the engine reconciles native state. Never replay historical approvals as new actionable requests.

The caller supplies a transactional `ImportSink`: begin, append agent/item, store blob, commit, rollback. Await every write for backpressure. Commit publishes the imported thread only after stable source verification. Cancellation or changed files roll back. Large raw records and oversized lines use ADR 0006's native blob references. Attach raw once across text fragments, cap type and display metadata, and reject oversized canonical items before publication; transcript text is split into bounded items. Sinks must persist incrementally and serve windowed items under ADR 0006, never acquire a full-history projection to import. The default archive runs entirely in the history worker. The daemon then streams committed archive rows into its event store in a second worker, using one SQLite transaction for events, provenance, agents, items, output streams and raw chunks. Source changes or cancellation cannot expose partial history. The daemon publishes committed events in batches of 16 and removes archive staging after success. Before taking the Store write lease, await the host-owned `HistoryAdapterPort.pausePersistence(signal)` barrier. It drains current engine persistence and pauses callback ingress for all of its writers, including exit delivery, with bounded transport backpressure. After commit or rollback and notification delivery, release the Store lease, then resume ingress in `finally`. Active continuations without this port refuse publication before taking the lease; their private archive remains available for retry. Command writes can still fail promptly during the lease, while reads see the previous committed database. Unsolicited live callbacks never enter that rejection interval when the barrier contract is satisfied. No transcript-sized in-memory replay queue is introduced. Cancellation uses a shared atomic flag so synchronous worker SQLite loops remain cancellable.

## Protocol and wire additions

Add schema-only `history.ts` through the `@ace/protocol/history` export. Define session summaries, list requests with workspace cwd and bounded cursors, import requests, unsupported outcomes, and imported provenance. Extend Thread additively with optional imported provenance including NativeRef and instance ID. Wire contracts include `history.list`, `history.scan`, `history.import`, and `history.continue`, added to the shared wire union. Read scope permits listing; operate scope permits scanning, importing and continuing. Continue also checks thread readability. Source paths and launch environments stay host-local. Import matches the registered source cwd to the requested workspace and is idempotent by source. Imported threads use the daemon's existing snapshots, item paging, output reads and retention. Metadata-only archive must check persisted Store thread existence, without requiring a live engine snapshot. A socket regression archives an imported thread and verifies that retried command IDs return the same receipt with one persisted effect, covering integration finding I17.

Continuation returns the existing adapter `resume: {nativeSessionId}` context plus instance ID and cwd. Fork continuation requires a caller-supplied native fork operation which returns the new native ID. ace never fabricates fork IDs or claims capabilities a provider lacks. No provider process is launched during discovery or import. CLI startup scans default homes, with host-local `ACE_HISTORY_INSTANCES` overriding them. The daemon accepts a home-bound adapter resolver and engine frame/exit consumers through `HistoryAdapterPort`; continuation calls that adapter's native `openSession` and `send`. Fork persists the returned native ID. Resolve that persisted root-agent ID before both resume and a subsequent fork, including after native exit or daemon restart. Use imported provenance or the registered source only when no newer root-agent identity exists. Reject forks on active sessions before invoking the native operation. Do not cache sessions which exit during startup; daemon lifetime owns active sessions across client reconnects. Without the adapter/engine port, return unsupported. Concrete adapter factories and the engine actor from ADR 0007 remain their respective workstreams, rather than being duplicated here. Legacy OpenCode messages sort by stored creation time in a private SQLite file; part IDs give deterministic part order. Small part inventories sort at most 16 paths, then spill to disk.

## Engine integration (2026-10-07)

The production history port delegates native resume to the existing engine session owner. The imported root keeps its agent and native session identity; historical items stay paged in Store rather than being replayed into engine memory. Import alone starts no provider process. Continue opens the native session without sending a synthetic prompt, and later messages use the normal engine queue, lifetime, frame handling and Store publication backpressure. Fork remains unavailable through this port until the engine owns native fork selection.

Session summaries optionally report continuation availability separately from import fidelity. New thread and Setup share a lazy, project-filtered history list; unsupported providers offer import with explicit copy. Resumed imports pin their original host-local home in a private binding, and reject removed or rebound homes on subsequent starts. Warm startup reuses persisted fingerprints and summaries; unchanged sources require no transcript reads or recency-summary rewrite. Watch scheduling remains owned by the scan service, including the independent idle-performance workstream.

## History display and readable formats (2026-10-08)

Project history lists omit context-only sessions and identifiable noninteractive runs. They prefer native summaries and names, then the first cleaned user prompt, then a date title. One sanitizer in history-import also cleans imported user messages. The private index is refreshed once on this format upgrade, keeping old cached rows hidden until rescanned. Codex session-index names override state titles; unchanged title files skip content reads.

Self-contained Codex paginated JSONL uses the existing response-item decoder. The mode alone no longer refuses import; external `history_base` references still require a complete provider export. OpenCode's schema-probed v2 `session_message` rows now map ordered user text and assistant text, reasoning and tool content. V2 rows take precedence over duplicate legacy rows. Unknown schemas and records above the SQLite decoder limit still refuse import. Unsupported children make their root unopenable too.

The additive `history.list` fields `search` and `openableOnly` allow bounded server-side search and pages of sessions that can open. New thread shows four recent sessions for its project and a lazy provider-grouped search dialog. Empty sections disappear; Import and supported Continue actions reveal on hover or keyboard focus and remain visible on touch devices. No provider process starts during discovery or import.

## Security

Only host-registered absolute homes are scanned. Reject symlinks and special files, enforce directory and entry limits, validate input through Zod, and verify real paths stay inside the home. Provider files are opened read-only with no-follow semantics. SQLite uses read-only mode; immutable mode is safe only for caller-declared offline snapshots without WAL or journal files. A read-only SQLite handle can update a live database's shared-memory read marks. For live homes, stream a fingerprint-verified private copy of the database and WAL under the ace index directory, then query that copy read-only. Never open source shared-memory files through SQLite. Active rollback journals return a retry reason. This costs O(database bytes) on a changed database and avoids violating source preservation. No checkpoints, migrations or pragma writes run on provider databases. Validate index containment before creating directories. Indexes and blobs belong to ace, outside provider homes, with private permissions. Shutdown aborts operations, returns suspended generators, closes databases and removes private snapshots before terminating workers. Imported transcripts may contain secrets and use the same authenticated access and retention as ace-created threads.

## Performance and tests

The worker owns synchronous SQLite and JSON decoding. One operation is in flight per service. File sampling batches hold at most 16 paths. Custom sinks pull at most 16 bounded packets; the default archive writes inside the worker without sending items over IPC. A verification barrier follows sink writes before commit. Lists use SQLite ordering and capped pages; no transcript cache grows with history. JSONL record memory is capped; oversized lines stream to blobs from source byte ranges. Non-gating benchmarks cover 5,000-file cold/warm scans and streaming import, with throughput and peak RSS.

Public API tests use temporary homes and actual SQLite files. Cover each supported provider, fixture-derived content, multi-home identity, warm scans counted by actual content reads, partial final lines, unknown data, cancellation, changed sources, lineage refusal, sidechains, deletion, large records and backpressure. Compare source bytes before and after scans/imports. Observe real FileHandle, readFile and stream reads through an injected worker factory to verify warm scans independently of reported counters. Async progress acknowledgments make source-change tests deterministic. Include public regressions for database fallback, identity, account removal, advancing cursors, selected branches, completed calls, paused shutdown, rejected index paths, and raw amplification. Test authenticated daemon routes, home-bound continuation, transactional publication, output/blob retention, and cancellation. Socket regressions cover repeated forks after exit/restart, every item and exit during overlapping publication, refusal of unsafe publication without backpressure, and cancellation/retry at the persistence barrier. Synchronize overlap through committed Store notifications and promise gates rather than sleeps. Maintain mutation cases for public behaviour tests, including all five review survivors. The owner requires tests to run once at merge and prohibits local tests, probes, mutation runs and benchmarks. This revision uses only formatting, lint, type checking and file-size checks. Behaviour, mutation and revised performance verification needs run at merge. Cases are marked "not executed (tests run at merge)". Historical benchmark numbers remain labelled as a pre-review baseline.
