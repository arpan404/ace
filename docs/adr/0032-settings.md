# 0032: Layered settings shared by the daemon and clients

Date: 2026-10-02. Status: accepted.

## Context

The supplied competitor inventories describe t3code scopes, themes and keybindings, Claude's project launch configuration, and Codex's local environments and automation settings. They do not establish a common cross-client contract for per-key provenance, invalid-edit recovery or preserving newer settings. ace needs that contract before its clients arrive. These inventories inform requirements only. No competitor implementation is reused.

## Decision

`@ace/settings` owns resolution and file I/O. `@ace/protocol` owns schemas only. Settings are flat dotted keys inside `{ "version": 2, "settings": { ... } }`. Keys describe provider/model/tier/effort for coder, reviewer and planner, approvals, notifications, remote preferences, automation defaults, plugins and opaque theme/keybindings blobs. Values replace a whole key; blobs do not deep-merge.

Resolve each key from defaults, global `<dataDir>/settings.json`, workspace `<repo>/.ace/settings.json`, then thread `<dataDir>/threads/<id>/settings.json`. Return both value and layer. Thread files survive restarts. Scopes use daemon-owned workspace/thread IDs on the wire. The service accepts paths only at its trusted integration boundary.

Version 1 has the same dotted settings in `values`. Reading it renames `values` to `settings` and advances the version with minimal JSONC edits. Migration writes once. Unknown settings and document fields survive migration and writes. Unsupported versions produce a diagnostic rather than a speculative rewrite. Known keys validate independently; unknown keys remain opaque and are not exposed through typed `get`/`set`.

JSONC accepts comments and trailing commas. Use the MIT-licensed [Microsoft jsonc-parser](https://github.com/microsoft/node-jsonc-parser) documented parser and edit API. A pure visitor checks every decoded property and literal before materialization, rejecting duplicate names, prototype properties and credentials even when a later property would shadow them. Never accept the parser's recovery result when it reports errors. Preserve whitespace and comments around unchanged values. Moving the v1 container can relocate its comments; ordinary sets edit one value.

Writes reread the current file and fully validate any changed source. For an identical validated source, existing scalar assignments reuse validated offsets and the cached UTF-8 byte count, validate the replacement and adjust the bounded offset index; complex values and insertions use the full decoder. Write an exclusive temporary sibling, fsync it, rename over the destination and fsync the directory. Each file serializes daemon operations with a bounded queue. An external edit that completes before reread is retained. Between reread and rename, the last rename wins for the entire document. There is no cross-process compare-and-swap. Readers see complete old or new files, never a torn write. Invalid files block writes and retain the last good in-memory document.

Watch parent directories, including the nearest existing ancestor when `.ace` has not been created yet. Native ancestor notifications can miss directory creation. While the destination parent is absent, also use nonpersistent 500 ms stat polling on the destination file; stop that fallback when reattachment can watch the actual parent. The 64-file cache bounds fallback registrations. This combines native notifications with the [Node filesystem polling boundary](https://nodejs.org/api/fs.html#fswatchfilefilename-options-listener), and avoids continuous document reads for unchanged files. Reattach after directory changes and debounce bursts with one replaceable timer per file. Watcher health is separate from document validity: a successful read does not clear a failed-watch diagnostic, and the debounce boundary retries registration. Diagnostics describe parse, validation, version, secret, size or I/O failures without echoing values. Deleting a file restores lower layers. Shutdown stops watchers and drains writes. Repeated identical document diagnostics do not notify subscribers again.

## Protocol additions

Add authenticated `settings.get`, `settings.set` and `settings.subscribe` requests beside existing commands. Remote reads/subscriptions require `read`; assignments require `operate`, and `admin` includes both. Settings deliveries exceeding the configured socket byte cap close with 4009 and require a fresh subscription. Async file operations stay outside synchronous SQLite receipt transactions. Request IDs correlate `settings.result` responses. Sets are assignments and safe to retry, but have no durable receipt deduplication. `settings.subscribe` sends an initial result then `settings.changed` messages for selected keys whose value or provenance changed. Existing `unsubscribe` releases either kind of subscription. Reconnect by fetching/subscribing again; settings notifications are not event-log replay. Diagnostics are included in reads and delivered to active selectors as `settings.diagnostic`.

## Security

ADR 0002 applies to every layer and opaque blob. Reject recursively named token, API/private/secret key, password/passwd/pwd, credential and authorization fields, and recognizable bearer tokens, provider key prefixes and PEM private keys in string values. Generic `key` fields are forbidden, while the declared `clients.keybindings` setting is allowed. These checks are a guardrail, not a classifier for arbitrary random strings. Provider login, remote device credentials and relay keys belong to their respective secure stores. Remote settings are preferences and never activate transport or grant authority. Workspace approvals are preferences; an execution engine must enforce its trust and capability rules separately.

Workspace roots are pinned to their canonical identity; `.ace` and its settings file cannot be symlinks. Recheck containment before reading/writing and immediately before rename, including migrations. This intentionally rejects even in-workspace symlinks. Physical files and logical layers have separate identities so aliases retain scope-specific provenance. Every workspace acquisition attaches its permanent guard, including a physical file previously loaded globally. Workspace scopes acquire that layer first so a cold alias cannot migrate globally before containment. Later global acquisitions find retained workspace guards by file path, including after file eviction. Once guarded, a shared file remains guarded for global operations too. Canonical identities outlive file-cache eviction; accepting a fresh identity after eviction would reauthorize a replaced root. Retain at most 64 workspace identities for the service lifetime and reject additional distinct roots with a limit error. Closing the service releases them; inactive thread scopes still use the file LRU.

Atomic writes hold the original parent directory handle through rename and directory fsync. If a failed write finds the parent replaced, temporary cleanup searches at most 128 sibling entries for the original directory inode/device, without following replacement symlinks. If that directory moved beyond the sibling directory or the search limit, return an explicit I/O error instead of claiming cleanup succeeded. This bounded recovery covers the reported `.ace` to `old-ace` swap. It is not protection against arbitrary concurrent filesystem relocation.

Documents are capped at 1 MiB and each client blob at 64 KiB. Cap JSON depth, file handles, subscribers, selected keys and queued operations. Client payloads validate with Zod and file reads enforce the byte cap while reading. Never include file content or rejected values in diagnostics.

## Performance and testing

Index subscriptions by selected key and layer file so a change visits only affected subscribers, then compares effective value and provenance. Keep all unknown fields in validated source text, but cache only schema-known values for resolution; resolution visits at most three files. Full parsing occurs for changed external documents, migration, insertion and complex-value updates. Scalar updates reuse cached validation and a fixed-size key-offset index. Scalar byte-cap checks subtract the old raw literal byte length and add the replacement byte length, including escaped Unicode. Scalar cache copies and freezing visit only the 31 known keys. Whole-file reads, source equality, string replacement and atomic publication still cost O(document bytes), bounded at 1 MiB. Preserving comments and unknown source while atomically replacing a JSONC file requires that whole-file I/O; scalar updates do not parse, scan byte counts or traverse unknown data again. A 64-entry LRU evicts inactive healthy scopes; operations, subscriptions and diagnostic-bearing last-good documents pin their entries. Cold acquisition and per-file queues each cap at 64 pending operations. Non-gating benchmarks measure cached gets, indexed notification fan-out, debounced watcher scheduling, changed-document reconciliation and scalar writes with 0/16/256/879 KiB of unrelated data, with throughput and peak RSS. Added workloads cover 10,000 unknown keys, native workspace containment reads, durable writes and failed-directory-swap recovery.

Tests use public service APIs, temporary files and real authenticated WebSockets. Cover precedence/provenance, one-time migration, unknown-key round-trips, comments, external-write ordering and atomic visibility, invalid-edit recovery, debounced bursts, selective delivery, secrets, limits, restart persistence and socket cleanup. Add regressions for duplicate/escaped/shadowed secrets, prototype properties, symlink replacement during writes, persistent watcher diagnostics/retry, aliased provenance and inactive-scope reuse. Guard aliased migration/read, changed canonical roots after file eviction, workspace identity backpressure, temporary cleanup, unchanged diagnostic suppression and UTF-8 capacity with public behavior assertions. Real file-handle durability gates verify both fsync stages and shutdown draining; a sparse oversized file verifies bounded allocation before reading. Inject watcher/timer boundaries for deterministic burst tests; no sleeps or wall-clock assertions. The owner now requires tests and benchmarks to run only at merge. Write behavior tests and at least eight corresponding production mutation cases; mark execution pending at merge. Delivery runs only formatting, lint, type checks and file-size checks. See `packages/settings/VERIFIER-FOLLOWUP.md` for the current evidence and historical runs before that rule.

## Settings controls follow-up (2026-10-08)

Permission defaults use provider-native mode IDs (ADR 0061). `permissions.providerModes` is the one key that merges by provider across layers: a project can override Claude without freezing its inherited Codex choice. Reads and subscription entries include optional `localValue` for this key, holding only the requested layer's assignments. Removing one local provider restores inheritance. Other settings still replace whole values.

Provider favourites, hidden models, custom models, enablement, executable overrides and catalog filters live in global `providers.configuration` (ADR 0036). Clients migrate their old local favourite list into these preferences once, removing the local list only after a successful save. Desktop work preferences use the existing desktop bridge (ADR 0054).

Project folders are global user preferences. Socket assignments validate accessible canonical directories with the existing project policy before replacing the allowlist. An empty list restores the home-folder default. The folder refusal UI reviews the requested root and can add it without exposing a setting key.

Remove unused notification, log-retention, automation timezone/concurrency and plugin settings from the typed registry, along with the unused daemon-side login preference. Existing unknown JSONC values remain preserved. Remote enablement and transport remain because the remote pairing implementation reads them. Desktop notification and login controls continue to use the desktop contract.
