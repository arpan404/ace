# 0058: Draft discovery, workspace changes and client file channels

Date: 2026-10-03. Status: accepted.

Extend ADR 0057 through correlated requests and durable thread commands. Keep the conductor and all UI work outside this change.

A New thread already has a device-owned context draft. `commands.list` takes either `threadId` or `draft: { draftId, workspaceId, provider, instanceId? }`. The host verifies draft ownership, expiry and the canonical workspace root before and after discovery. Discovery reads file and builtin commands without creating an empty thread or opening a provider session. Session-only runtime commands cannot leak into the draft catalog. An explicit instance must match the provider; absent selection uses the first configured provider instance. Clients should pass their selected account instance. Retain `thread.prepare` for agent-control callers, add `mode` and `baseBranch`, and use `thread.create` for the first user send from a context draft.

`thread.workspace.set` changes a quiescent thread's local/worktree mode and checked-out branch. Reject pending delivery, live agents, tools, interactions, background work and owned terminals. Persist `details.workspaceChange` as preparing before closing the provider session or touching Git. Reject dirty work unless `allowUncommitted` is explicit. Git still refuses a switch that would overwrite changes; this flag never forces, discards, stashes or copies files. Uncommitted files remain in their original worktree when changing mode. A branch supplied with the workspace command names an existing checked-out branch; initial `baseBranch` selects the base for a new isolated ace branch.

After success, atomically bind the session cwd and publish applied details. Start the next provider session fresh with a bounded portable transcript handoff because provider-native cwd migration is not portable. The event marks that handoff lossy. Remove any old native fork selection. Validation failures preserve the old binding; uncertain failures and interrupted preparation retain a durable fence until explicit retry. Filesystem owners refuse fenced roots. Thread execution status remains derived from the whole tree; workspace progress is separate metadata.

Thread-scoped `files.request` resolves the persisted execution root instead of `ACE_WORKSPACE_ROOT`. One service per root retains upload offsets, CAS publication, hashing and device ownership. `files.pull` and `files.chunk` carry at most 64 KiB of bytes as base64 in correlated frames. A download consumer requests one chunk at a time; an upload source advances only after the previous durable offset acknowledgement. This avoids whole-file buffering across a tab, worker and daemon. Each connection admits four channels and eight pending controls. Legacy binary frames remain available on their original low channel IDs; scoped channels use the upper half of the ID range.

`ClientApi.downloadFile` returns an async byte iterator. `ClientApi.uploadFile` accepts an async byte source yielding at most 64 KiB per chunk, a known size, SHA-256 and destination CAS version. Both concrete clients and shared-worker clients use these APIs. `files.cancel` releases a channel; `files.abort` cleans up an opening channel by source request ID after cancellation or timeout. Disconnect and tab detachment release channels. Upload state remains resumable through `upload.resume`; retention remains owned by the files service. Workspace/root and authorization checks repeat at every chunk and publication boundary.

History import and continuation retain optional request IDs for old callers and emit `history.operation.progress` for correlated clients. Progress is a push, never a terminal request reply. `Client.request` accepts a caller-supplied request ID so the client can associate progress before sending. The worker forwards progress separately and returns only the final correlated response. Errors preserve correlation and safe messages.

`registry.bind` accepts a `local:` ACP identity, installed executable and literal argv under admin and operate authorization. The registry resolves and hashes the executable, rejects package runners and impersonation of official identities, and persists its existing immutable inventory. Binding launches nothing and accepts no credential environment. Generic ACP capabilities and limited visibility remain governed by ADR 0044.

Browser subscriptions carry optional subscriber IDs. The shared worker assigns each tab its own ID, makes repeated subscription idempotent and removes only that tab on unsubscribe or detachment. The daemon retains one physical subscription until the last subscriber leaves. Old direct callers share the legacy subscriber ID. Frame acknowledgement remains connection-owned.

Git command receipts distinguish `git_head_moved`, `git_conflicts`, `git_hook_failed`, `git_auth_failed` and `git_failed`. Classification reads bounded local diagnostics; receipts expose codes without command output, paths or credentials. Commit uses [Git Trace2 hook child events](https://git-scm.com/docs/api-trace2) to detect silent failing hooks. Branch changes use [Git switch](https://git-scm.com/docs/git-switch) without destructive flags.

The real-daemon e2e script reads `ACE_E2E_TURN_DELAY_MS`, `ACE_E2E_LIMIT_AFTER_TURNS` and `ACE_E2E_LIMIT_RESET_MS`. Defaults preserve instant unlimited turns. The adapter testkit owns deterministic delayed completion and quota recovery with injected clocks/timers. It never starts a provider CLI. Setting a positive delay exercises queued delivery; setting a positive limit exercises usage-limit failures and recovery. Tests and e2e scenarios require execution at merge under the owner's policy.
