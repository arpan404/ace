# 0015: Local scheduled and triggered agent tasks

Date: 2026-10-02. Status: accepted.

## Context

The supplied competitor inventories describe Codex schedules, event triggers and a scheduled inbox; Claude routines and GitHub auto-fix; Cursor automations; and Antigravity scheduled tasks. t3code has no scheduler. ace needs these workflows across providers while keeping execution on the user's machine. Cloud routines do not solve downtime, local workspace access or whole-tree completion for ace. These inventories inform the feature scope only; all implementation is written fresh.

Primary references: [RFC 5545 recurrence rules](https://www.rfc-editor.org/rfc/rfc5545#section-3.3.10), [crontab grammar](https://man7.org/linux/man-pages/man5/crontab.5.html), [GitHub conditional requests](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api#use-conditional-requests-if-appropriate), and [gh api](https://cli.github.com/manual/gh_api).

## Decision

`@ace/automations` owns pure recurrence evaluation, dispatch decisions and template rendering, plus thin SQLite, timer, workspace and gh process adapters. No scheduling dependency is added. Intl supplies the installed runtime's IANA timezone data. All clocks, random draws, timer drivers, run IDs and gh spawners are injected.

RRULE supports FREQ=MINUTELY/HOURLY/DAILY/WEEKLY/MONTHLY/YEARLY, INTERVAL, BYDAY, BYHOUR, BYMINUTE, COUNT and UTC UNTIL. WEEKLY starts Monday. Ordinal BYDAY is supported for MONTHLY and YEARLY. Unsupported fields fail at configuration time. DTSTART is an epoch millisecond instant, with seconds required to be zero. Cron has five numeric fields, lists, ranges and steps; Sunday accepts 0 or 7. Restricted day-of-month and day-of-week use cron's OR rule. No macros, seconds, names or extensions.

Calendar evaluation skips nonexistent local times and invalid dates. A repeated wall time runs once at its first instant, including cron. Monthly January 31 does not spill into February, and annual February 29 skips non-leap years. Search is bounded and reports an explicit error when its budget is exhausted, rather than silently declaring a schedule finished. Evaluation jumps past history for uncounted rules. COUNT uses a persisted ordinal cursor for incremental advancement. Initial lookups and downtime recovery enumerate new occurrences with a bounded work budget.

Schedules and their next nominal time and jittered deadline persist in SQLite. Startup applies `skip` by advancing beyond now or `run_once` by keeping one overdue occurrence and advancing beyond now after dispatch. Jitter is drawn once per scheduled occurrence and survives restart. It is capped just before the following nominal occurrence so a large jitter setting cannot swallow later runs. One indexed query returns the next deadline; the timer shell arms exactly one timeout. Long delays use the platform's maximum timeout and re-arm, never a periodic scheduler poll. GitHub polling is necessarily periodic I/O, but its deadlines share this same timer. At most four gh requests are active; an indexed schedule-only deadline query keeps slow polling from delaying agent schedules. Excess poll sources stay due on disk until a slot opens.

Admission and durable event deduplication happen in one SQLite transaction. Per-automation active counts include queued, running and human-waiting executor work. At capacity, arrivals are recorded as skipped, with no unbounded waiting queue. An executor accepts an idempotency key, provider, model, rendered prompt, workspace and worktree choice. Its promise resolves only when the entire thread tree has settled; a human wait must keep it pending. Startup reconciles unfinished rows by this key before admitting new work. Execution observers receive an AbortSignal. Stopping releases observers while retaining engine-owned threads and durable rows for recovery. One bounded observer map owns at most 256 subscriptions; obsolete results cannot finish rows. A pure lifecycle state machine serializes startup and teardown with constant memory. Teardown rejects reentrant startup rather than queuing resource acquisition inside cleanup; an explicit later start recovers normally. A stop requested during startup disables admission immediately and drains cleanup after startup registers its resources. Exactly-once external creation cannot be guaranteed by SQLite alone; the engine must implement idempotent creation/recovery. This package never invokes an agent CLI.

GitHub sources use bounded GETs via the user's logged-in `gh api`, with ETag/If-None-Match. PR updates, failed workflow runs, review comments and newly applied issue labels become typed trigger variables. Resource versions form stable event keys. The first successful fetch establishes a baseline, avoiding a burst of historical tasks. Poll snapshots and ETags persist together only after event delivery succeeds. Revision and lifecycle checks protect each admission and the final snapshot write, including configuration changes from run notifications. Pagination is bounded; overflow is an explicit error rather than silently dropping events. File changes arrive through an injected subscription interface pending the workspace package merge. Replacement subscriptions are prepared before committing configuration; failed preparation preserves the previous definition. Cleanup isolates each unsubscribe failure. Manual requests carry a caller-supplied idempotency key.

## Protocol and wire additions

A new schema-only protocol module exports automation definitions, schedule/trigger unions, run records, inbox pages and request/response envelopes for `automation.put`, `automation.remove`, `automation.run`, `automation.list` and `automation.inbox`. These envelopes are separate from the current daemon wire union to avoid conflicting edits across workstreams. The daemon integration owner must route them through existing authentication and command receipts and publish committed run changes. This deliverable exports a service API rather than changing the daemon entrypoint while the engine and workspace services are in flight.

The scheduled inbox returns bounded, cursor-paged rows with automation title, trigger, thread reference, outcome, result summary and timestamps. Running work remains running until the executor reports tree completion.

## Security

No provider or GitHub credentials enter automation definitions. gh uses its existing login. Fixed argument arrays avoid shell expansion; canonical repository endpoints reject dot segments and requests target github.com. gh uses the existing provider-kit POSIX process-group owner through an injectable spawner. Aborts reject independently of pipe closure and terminate the process group. Response bytes, process duration, templates, variables and results have caps. Trigger text is untrusted prompt content, not an executable template language. Templates permit only named variable substitution, with missing variables producing a failed run. Existing engine approval and workspace policies still apply to unattended tasks. Database files belong in the daemon's private state directory.

## Performance and testing

Definition and deadline rows are physically separate from snapshots. Startup migrates existing inline state in one transaction, iterates metadata and reads only required schedule cursors. Admission and listing never decode poll state. A poll parses its snapshot once and builds a bounded resource index, with O(snapshot + events) work for diff and admission rather than O(events × snapshot). Admission uses indexed active counts and event keys, with prepared statements and transaction boundaries. The timer reads an indexed minimum deadline instead of scanning all automation history. Memory holds only bounded definitions, one poll response and admitted executor tasks. Disk history is explicitly retained for audit and deduplication, with no in-memory history cache.

Tests exercise the public package API with temp SQLite, injected time and timer drivers, an executor fake and a real child process running a fake gh executable. They cover recurrence filters, DST gaps and folds, leap days, month ends, COUNT/UNTIL, downtime policies, jitter persistence, one timer, concurrency, crash recovery, outcomes, pagination, conditional requests and deduplication. Non-gating benchmarks measure recurrence evaluation, dispatch/admission and conditional-poll translation, composed polling/admission with large persisted snapshots, and supervised gh I/O. Each run commits before invoking callbacks, allowing callback-driven configuration edits without exposing a partially committed batch. Before delivery, at least eight production mutations must each cause a behavioral test to fail, then be reverted.
