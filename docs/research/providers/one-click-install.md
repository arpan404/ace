# One-click provider installation and sign-in

Researched 2026-10-08 against official vendor documentation, published install scripts and the official ACP registry. No installer, provider login or model request was run. No credentials or application bundles were read. Commands below describe vendor interfaces; implementations must remain clean room.

## Antigravity is installable

The official entry `antigravity-acp` was version 1.3.0 when checked. Publisher is Google LLC; its proprietary license links Google's terms. It provides Google-hosted ZIP archives for macOS, Linux and Windows on arm64 and x64. macOS/Linux launch `./agy_acp_server.par`; Windows launches `./agy_acp_server.exe`. Linux adds `--uid=`. The manifest includes no checksum, so an HTTPS download must not be labelled checksum-verified. [Official entry](https://github.com/agentclientprotocol/registry/blob/main/antigravity-acp/agent.json).

Google explicitly documents installation from the ACP registry in Zed. ace already owns registry planning, bounded downloading, archive extraction and installed-agent binding in `@ace/agent-registry`. Reuse that service, retain companion files, and bind the installed entrypoint to Antigravity's existing provider identity. There is no distribution reason for a download-only or "How to install" main action. [Google's Zed setup](https://antigravity.google/docs/ide/extensions/zed), [ADR 0044](../../adr/0044-acp-agent-registry.md).

The distinct `agy` CLI installs through `curl -fsSL https://antigravity.google/cli/install.sh | bash` at `~/.local/bin/agy`. Starting it triggers its own browser login if the CLI's keyring has no saved account. Google's docs do not establish that this signs in the ACP server. [CLI installation and auth](https://antigravity.google/docs/cli/install).

The ACP docs describe Google-account, enterprise, Gemini API key and Agent Platform authentication. They do not document an `agy_acp_server login` terminal subcommand. ACP's protocol-driven flow asks the server to `initialize`, then `authenticate` using an advertised agent-owned method. Terminal methods instead describe interactive arguments for the configured agent. Never invent a terminal login command or infer successful ACP authentication from `agy`'s presence. [Google's auth choices](https://antigravity.google/docs/ide/extensions/zed), [ACP authentication](https://agentclientprotocol.com/protocol/v1/authentication).

Before this change, discovery checked `agy`, the adapter launched `agy_acp_server`, and the install manifest checked `agy-acp`. Installation, discovery and launch now share the verified registry binding and its declared arguments/environment. No real vendor binary was run.

The owner's 2026-10-08 request authorizes the installed agent's own Sign in flow. [ADR 0002's amendment](../../adr/0002-local-cli-providers.md#amendment-installed-acp-agent-sign-in) records its boundary: ace implements no OAuth exchange and preserves credentials inside the agent. Unsupported authentication stays visibly unresolved; actual Google-account sign-in and eligibility were not exercised.

## Prerequisites and honest fallbacks

For npm-only installations, check both npm and the provider's required Node version. npm's official guide says the Node installer installs both Node and npm. The Node project publishes platform installers and archives at its download page. No first-party Node shell bootstrap was identified in this research; do not silently add nvm or another third-party manager. Offer `brew install node` when an existing Homebrew installation can perform it; otherwise explain that the Node installer must be completed and offer its official download page. [npm guide](https://docs.npmjs.com/downloading-and-installing-node-js-and-npm/), [Node downloads](https://nodejs.org/en/download).

Homebrew publishes its official `https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh` bootstrap. `NONINTERACTIVE=1` disables password prompts; default prefix provisioning can still require administrator access. A first install must explain that requirement and use the existing native terminal when interaction is needed. ace must not accept an administrator password. After install, resolve the actual Homebrew executable and refresh PATH detection rather than requiring an application restart. [Homebrew installation](https://docs.brew.sh/Installation).

Pi's official script uses `sh`. Its managed installation defaults to `~/.pi/agent/install`, and the executable defaults to `~/.pi/agent/bin/pi`. It may instead use an existing writable per-user or Homebrew bin directory on PATH. Its Node/npm provisioning requires a terminal confirmation, and Linux package-manager branches may need administrator interaction. Running that script without a terminal does not automatically resolve missing Node/npm. Keep the npm path when npm is present unless script ownership is supported correctly. [Official installer](https://pi.dev/install.sh).

Native Claude, Codex and OpenCode scripts can avoid installing npm solely for those providers. Archive-backed ACP installations can avoid both npm and Homebrew. If curl/bash/sh or an archive prerequisite is missing, name the missing tool and link its official setup rather than returning a generic install failure. A provider with no supported distribution for the host can use a "Get <provider>" link and explain the platform limit; an installable Antigravity ACP server must use Install.

## Integration recommendation and verification limits

Keep command allowlisting in `@ace/provider-kit/installers`, prerequisite and installed-owner checks in the existing planner, supervision and cancellation in the CLI-install service, and ACP archive/package installation in `@ace/agent-registry`. The shared provider row should derive its action from current installation, login and update facts. Refresh those facts after each completed operation; a zero installer exit is not proof of a signed-in provider.

Reuse #191/#192's bounded ephemeral login session and live native terminal. Pi and several ACP agents require their interactive native UI; do not manufacture an unattended login command. Antigravity requires an ACP-owned authentication path because no independent server-login CLI was documented. Source research does not establish end-to-end sign-in, quota eligibility or credential isolation for any untested distribution. Tests must use fake installers and fake provider login processes.

uv has an official standalone installer. Missing uv is installed through `https://astral.sh/uv/install.sh`, with `UV_INSTALL_DIR` pointing to the normal per-user binary directory and `UV_NO_MODIFY_PATH=1`. The registry resolves that installed executable directly, so a restart is unnecessary. [Installation](https://docs.astral.sh/uv/getting-started/installation/), [installer options](https://docs.astral.sh/uv/reference/installer/).
