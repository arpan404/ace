# Local provider SDK audit

Researched 2026-10-02. Recommendation: keep the Claude Agent SDK and Codex
app-server, complete the missing Claude controls, keep Gemini CLI on ACP, and
evaluate Qwen's daemon SDK before changing its transport. "SDK wherever possible"
means choosing the official interface that preserves approvals, child agents and
recovery, subject to [ADR 0002](../../adr/0002-local-cli-providers.md).

This audit reads the current official package implementations, rather than
assuming that a package named SDK exposes every CLI feature. It supplements the
[earlier provider research](README.md), which remains useful for recorded
behaviour. Cursor, OpenCode and general ACP changes belong to sibling audits.

### Local login and authentication

The Agent SDK is a local wrapper around the Claude Code executable, rather than the Anthropic Messages client SDK. Its source builds stream-json arguments and launches the executable in `sdk.mjs` transport `initialize`; `query`, exported from minified `tKe`, creates that transport and streams the input. `Options.pathToClaudeCodeExecutable` overrides the bundled default. The adapter already discovers `claude` through provider-kit, passes its resolved path, merges the inherited environment and supervises its process through the SDK's custom spawn hook. Sources: `sdk:sdk.mjs#tKe/BR/transport.initialize`, `sdk:sdk.d.ts#Options.pathToClaudeCodeExecutable` at 1979; `ace:src/session.ts#openSession`, `ace:src/sdk-process.ts#spawnSdkProcess`; [official comparison](https://code.claude.com/docs/en/agent-sdk/overview#compare-the-agent-sdk-to-other-claude-tools).

This can technically use the user's existing local CLI login. Claude Code's documented authentication precedence includes subscription OAuth from `/login`, and credentials remain managed by Claude Code. Do not add key entry, OAuth extraction, an ace login flow, `getOAuthToken`, a cloud session transport or a hosted SDK environment. Avoid `--bare`, which the installed CLI help says does not read OAuth/keychain credentials. Sources: [Claude Code authentication](https://code.claude.com/docs/en/authentication#authentication-precedence), `claude --help` entry for `--bare`; repository ADR 0002.

The technical ability is distinct from vendor product permission. The Agent SDK overview still restricts third parties offering claude.ai login/rate limits without approval. A June 16 support article's June 15 update says the announced separate SDK allowance was paused and subscription limits still apply to SDK, `claude -p` and third-party usage. Keep ADR 0002's local-only boundary and do not portray either source as authorization for a hosted integration. Sources: [SDK overview](https://code.claude.com/docs/en/agent-sdk/overview#get-started), [current support update](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan).

### Normal coding experience

The adapter sets `settingSources:[]` and omits `systemPrompt`. The SDK's `Options.settingSources` says `[]` disables filesystem settings and `project` is necessary to load CLAUDE.md; `Options.systemPrompt` provides the `claude_code` preset. Runtime `BR` initializes the omitted system prompt field to an empty string before transport creation. Official docs clarify the resulting behavior is a minimal tool-calling prompt, while `claude -p` defaults to the full coding prompt. This means merely choosing the official SDK does not reproduce the user's normal coding environment. Sources: `ace:src/session.ts#query options`; `sdk:sdk.d.ts#Options.settingSources/systemPrompt` at 2238-2249/2302; `sdk:sdk.mjs#BR`; [official system prompt defaults](https://code.claude.com/docs/en/agent-sdk/modifying-system-prompts#how-system-prompts-work).

Recommendation: expose an explicit configuration policy with normal local coding mode using the Claude Code preset and selected user/project/local sources, plus a deliberately isolated mode for tests or opt-in isolation. Keep `permissionMode:'default'` explicit, because the recent official changelog documents that omitted mode can start in auto mode. Normal settings may load hooks/plugins/MCP and affect tool availability; document and observe those effects rather than silently discard the user's configuration. Source: same adapter/options evidence; [official changelog 0.3.286](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md#03286). This is a product recommendation, not evidence that existing isolation was accidental.

Outgoing user messages also omit `origin`; the current `SDKMessageOrigin` docs say hosts relaying genuine keyboard input should stamp `{kind:'human'}`, and absent origin fails strict human-trust checks. Route provenance from the shared send intent. Do not mark scheduler, tool, model or orchestration content human simply to make priority `now` work. Sources: `ace:src/session.ts#send`; `sdk:sdk.d.ts#SDKMessageOrigin` at 5335 and `SDKUserMessage.origin`.

### SDK model discovery instead of duplicate raw initialize

`packages/models/src/discover.ts#claudeInitialize` currently implements a separate control-response parser and raw stream-json `initialize` request for Claude, with strict empty MCP configuration and disabled filesystem settings. `createModelDiscovery` launches the user's executable and normalizes `{models}` through `normalizeClaude`. The package has no Agent SDK dependency. Sources: train SHA `packages/models/src/discover.ts#claudeInitialize/createModelDiscovery`, `packages/models/src/normalize.ts#normalizeClaude`, `packages/models/package.json#dependencies`.

Recommend a small-medium migration of the Claude model discovery path to the official SDK's empty streaming-input Query with the resolved user's executable, provider-kit custom spawner, current isolated metadata-only settings, bounded cancellation and finally cleanup. Invoke `supportedModels()` and adapt its returned array to the existing normalization envelope. Runtime `supportedModels()` returns `(await this.initialization).models`, so it does not send a prompt or start a model turn; do not use a dummy prompt. Reuse a shared narrow process bridge through a public package API instead of importing adapter internals or duplicating `spawnSdkProcess`. Source: `sdk:sdk.d.ts#Query.supportedModels` at 3008; `sdk:sdk.mjs#Query.supportedModels` at byte offset 1159910 in 0.3.288; current models and adapter source cited above. This recommendation is for later feature implementation only; no Query was created during this audit.

Test the public model-discovery result, cancellation/exit/output limits and process cleanup against the synthetic local CLI. Assert that the synthetic transcript receives initialize/control traffic and no user prompt. Existing metadata discovery remains isolated even if the live adapter's user-experience policy begins loading project settings. No paid fixture is necessary to prove the transport sends no prompt, although an owner-approved initialize-only installed-CLI check may confirm compatibility.

## Codex

### What the TypeScript SDK actually wraps

The npm `latest` tag resolved to `@openai/codex-sdk` **0.160.0**. Its package
depends on `@openai/codex` 0.160.0. `CodexExec.run` launches the executable with
`["exec", "--experimental-json"]`, writes the prompt to stdin, then closes stdin.
It does not launch `proto` or provide an app-server JSON-RPC client. Each
`Thread.run` or `runStreamed` invokes that process again. `resumeThread` only
constructs a thread handle; the next run adds `exec resume <id>`. [C1]

There is an important distinction underneath that wrapper. The official Rust
source snapshot inspected here implements `codex exec` through an
`InProcessAppServerClient`, but exec filters and converts its events and handles
server requests itself. Thus app-server inside exec does not give the SDK's
caller app-server's controls. [C2]

The SDK can satisfy ADR 0002 technically: set `codexPathOverride` to the user's
resolved executable, preserve the user's home/environment, and omit `apiKey` and
`baseUrl`. The constructor otherwise resolves its npm CLI dependency, and an
explicit `apiKey` is put into `CODEX_API_KEY`. ace must not use those defaults to
bundle a replacement CLI or introduce its own provider authentication. [C1; ADR 0002]

The official docs separately describe a Python SDK backed by app-server. That is
a different SDK; it does not change what `@openai/codex-sdk` wraps. A Python
sidecar adds another runtime to a TypeScript/Node project and is not recommended
for this migration. [C4; ADR 0003]

### Capability comparison

### Current adapter and remaining work

The integration adapter already resolves the installed binary, uses
`experimentalApi: true`, resumes sessions, streams deltas, routes server
requests, steers, manages the native queue, discovers late children and interrupts
known descendant turns/terminals. Do not rebuild those behaviours in an SDK
wrapper. Evidence: ace `packages/adapter-codex/src/session.ts`
`openCodexSession`, `session-commands.ts` `createSessionCommands`, `translator.ts`
`createCodexTranslator`, `translate-delta.ts`.

The gaps are at the control and service boundaries:

- `codexCapabilities` advertises `fork`, but `ProviderSession` has no fork
  operation and `openCodexSession` only opens start/resume. Implement the daemon's
  existing optional `HistoryAdapterPort.fork` with native `thread/fork`, including
  returned identity and home ownership. Do not add fork to the text-input path.
  Evidence: ace `capabilities.ts` `codexCapabilities`, engine-api
  `ProviderSession`, daemon `history-continuation.ts` `HistoryAdapterPort`.
- The adapter has no `review/start` command. Its plan-review response uses
  `turn/start` in collaboration mode, which is a different workflow. Integrate a
  native review control with the existing `packages/review` and daemon review
  service. Evidence: ace `session-commands.ts` `resolve`, daemon `review.ts`;
  generated `ReviewStartParams`.
- The catalog already discovers models and tier parameters. Runtime
  `SessionContext` has only `model`; the session's `turn/start` does not accept
  catalog effort/tier selections. Connect catalog resolution to the existing
  command boundary instead of introducing another model list. Evidence: ace
  `packages/models/src/discover.ts` `createModelDiscovery`, `normalize.ts`
  `normalizeCodex`, engine-api `SessionContext`, adapter `sendTo`.
- Rate-limit updates currently fall through to raw notices. Add reads and quota
  delivery through the accounts owner; preserve buckets and unknown fields. Do
  not treat a percentage of a subscription window as remaining token capacity.
  Evidence: ace adapter `createCodexTranslator` fallback; `packages/usage/src/quotas.ts`
  `QuotaWindow`; generated `GetAccountRateLimitsResponse`; probe.
- Capabilities are inferred from `version >= 0.159.1`, not confirmed per optional
  method. Keep that floor for the known translation contract, then gate optional
  controls on generated definitions and safe reads, and handle method/feature
  errors at invocation. Never probe `review/start`, `turn/start`, `turn/steer`,
  resume or fork as read-only capability checks. Resuming/forking a goal can cause
  automatic work; use `deferGoalContinuation` where supported for an explicitly
  requested fork. Evidence: ace `codexCapabilities`; generated `ThreadForkParams`;
  C3 `common.rs` experimental annotations.

`openCodexSession` spawns one app-server per ace thread. A shared process per
provider home is possible because app-server multiplexes threads, but that is a
separate lifecycle refactor with a larger crash domain. It is not necessary to
retain the better official interface. Defer pooling until process ownership,
home separation and reconnect subscriptions have their own acceptance criteria.
Evidence: ace `openCodexSession` spawn; C3 `ClientRequest` thread methods.

It does not, however, delegate execution or login to the installed CLI, and it does not simply select the CLI settings file's saved auth type. Existing credential compatibility was not tested. ## Qwen Code

### Query SDK

The published SDK wraps Qwen Code's stream-json control protocol, not ACP. `ProcessTransport.buildCliArguments` supplies `--input-format stream-json --output-format stream-json --channel=SDK`. `prepareSpawnInfo` defaults to the SDK-bundled CLI, but `pathToQwenExecutable` can select the user-installed command, native executable, or CLI JavaScript file. ace must always set its own discovered path and must never use the bundled default. `ProcessTransport` merges the user's process environment; CLI `loadCliConfig` selects explicit auth type, then saved `settings.security.auth.selectedType`, then environment inference. The SDK supports `qwen-oauth`, so the local installed-CLI path can keep login inside Qwen. Do not call SDK/device-login methods or pass/store provider tokens. [Transport](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/sdk-typescript/src/transport/ProcessTransport.ts), [CLI path resolver](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/sdk-typescript/src/utils/cliPath.ts), [CLI auth selection](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/cli/src/config/config.ts#L2190-L2194).

The SDK does offer useful features: an async iterable multi-turn input; `includePartialMessages` for text/thinking/tool-argument deltas; `canUseTool`; external and in-process MCP server configuration; session ID/resume/fork flags; turn `interrupt` separate from `close`/abort; runtime model/permission/effort changes; `getAvailableModels`, `getContextUsage`, `getUsageInfo`, `supportedCommands`, and `mcpServerStatus`. Native assistant/user/partial events carry `parent_tool_use_id`. Source CLI background registry emits `system/task_started` and `task_notification` with task/tool IDs. Preserve all system subtypes/raw fields and distinguish turn completion from live background work. [Query options](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/sdk-typescript/src/types/types.ts), [Query controls](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/sdk-typescript/src/query/Query.ts), [event types](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/sdk-typescript/src/types/protocol.ts), [background lifecycle](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/cli/src/nonInteractiveCli.ts#L1543-L1583).

The reason not to make `query()` ace's default is the implementation of human waits. `Query.startMessageRouter` awaits `routeMessage` for every line; a control request awaits `handleControlRequest`, which awaits `handlePermissionRequest`. `handlePermissionRequest` races the human callback against a 60-second default and auto-denies on timeout or callback failure. Changing the timeout to a large number still stalls incoming stream/control processing during that wait. The callback receives tool name, input, abort signal and suggestions, but drops native request `tool_use_id`; the router's request-local AbortController is not visibly connected to incoming cancellation, which cannot be read while the callback blocks the loop. This is a source-level risk, not an observed live defect. It conflicts with ace's indefinite human waits and preserving child progress. SDK initialization sends `hooks: null`; its control handler implements only `can_use_tool` and `mcp_message`, so exported protocol hook types do not establish a usable hooks callback API. [Query.startMessageRouter/routeMessage/handleControlRequest/handlePermissionRequest/initialize](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/sdk-typescript/src/query/Query.ts#L316-L609).

No server allowance/reset read API or stable rate-limit event is declared by Query's current public API. Usage dashboards and per-result model token accounting should not be called subscription rate limits. Native errors and retry notices must be preserved; no quota-exhaustion session was run. Published Query compatibility does not make installed 0.0.14 viable: the official README documents SDK 0.1.0 requiring Qwen >=0.4.0 and 0.1.1+ bundling the CLI. For user-installed overrides, use capability/flag detection and a control handshake, not that historical minimum as proof of all 0.1.17 controls. Reference SDK source corresponds to CLI 0.24.7. [Historical requirements](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/sdk-typescript/README.md#version-010-requirements), npm 0.1.17 `dist/index.d.ts`, `Query` and `SDKResultMessage`.

### Local daemon SDK

`DaemonClient` and `DaemonSessionClient` are official clients for `qwen serve`. They connect through an injected base URL/fetch, with REST+SSE default and optional ACP HTTP/WebSocket transports. They do not launch any executable, so `pathToQwenExecutable` does not apply to these classes. ace must supervise its resolved user's `qwen serve` on loopback, then pass the resulting local URL to the client. The CLI daemon's channel factory launches `process.execPath` with `cliEntry` from `QWEN_CLI_ENTRY || process.argv[1]` and `--acp`; this uses the CLI installation that is executing, not the SDK's bundled CLI. Ensure any `QWEN_CLI_ENTRY` override still points to the user's chosen installation. The underlying agent is still ACP, but the daemon adds lifecycle, history and replay services around it. [Daemon client options/constructor](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/sdk-typescript/src/daemon/DaemonClient.ts), [child spawn factory](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/acp-bridge/src/spawnChannel.ts#L465-L563).

The daemon SDK offers substantially more than a generic ACP client: capabilities, attach/create/load/resume/list/history; session status/resources/agent traces; child session lookup/cancellation; mid-turn message enqueue/remove/reconciliation; independent permission votes; runtime model selection and model configurations; usage/context reads; workspace/session hooks diagnostics; and MCP lifecycle controls. Its event stream accepts `Last-Event-ID` with an event epoch and signals `state_resync_required` when replay is unavailable or belongs to a prior epoch. `DaemonSessionClient` manages attach/detach, cursor tracking and transport retry, but ace must still reconcile its own canonical projection. No globally valid minimum `qwen serve` version was found; compatibility must be negotiated from the installed daemon's capabilities. The inspected reference implementation is CLI 0.24.7 and SDK 0.1.17; neither was installed into ace or executed. [DaemonClient methods](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/sdk-typescript/src/daemon/DaemonClient.ts), [DaemonSessionClient](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/sdk-typescript/src/daemon/DaemonSessionClient.ts), [feature registry](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/cli/src/serve/capabilities.ts).

Fork needs special care. `DaemonClient.branchSession` POSTs `/session/:id/branch` for a persisted history branch. `DaemonClient.forkSession` requires a directive and POSTs `/session/:id/fork`; the route calls `launchSessionForkAgent`, returns 202 and can start model work. Map canonical idle history fork to branch, never to directive-taking `forkSession`, and never use that method as a read-only capability probe. CLI ACP extension `sessionBranch` uses its session service's `forkSession` to clone history, showing that names alone are unreliable. [SDK branch/fork](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/sdk-typescript/src/daemon/DaemonClient.ts#L3697-L3786), [active fork route](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/cli/src/serve/routes/session.ts#L6024-L6062), [ACP history branch](https://github.com/QwenLM/qwen-code/blob/b12edec1401a28fc53cd9e714d5928b285071fc8/packages/cli/src/acp-integration/acpAgent.ts#L14007-L14166).

Native newer Qwen ACP is itself rich.
