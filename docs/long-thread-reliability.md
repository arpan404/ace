## Performance gate timeout correction

After the latest main merge, the orchestrator reported all 5,939 tests passing but the fast acceptance workload timing out at its unchanged 180-second limit. An idle run also exceeded ten minutes. CPU profiles identified repeated record reads and flushes during approval creation. Permission review searched the entire pending set for each approval and folded each review notice separately, repeating tree derivation. Commit `e8ed215f` keeps transaction baselines independently of the bounded LRU and enumerates record keys once per transaction. Consecutive completed transcript facts and approval opens derive status once; turn, control and recovery boundaries still derive immediately, and the final derivation happens before durable publication. Permission review uses the existing identity index and folds its notices together in the same atomic transaction. Every canonical fact, audit and notice remains durable before acknowledgement.

## Merge-time failure corrections

The orchestrator's latest main merge is `11958669`. The first executor case was reproduced with the planner waiting indefinitely for its plan. Explicit flushes let planning proceed and then left a worker waiting, isolating batch scheduling rather than artifact visibility.

- Durable frame batching now has its own injected scheduler. Its 1 ms flush deadline advances independently of the status/recovery clock. A frozen domain clock cannot hold provider acknowledgements, turn completion or thread observers. The existing deterministic acknowledgement regression explicitly injects its manual batch scheduler; that file was not run under this follow-up's restricted file list.
- Line intake delivers an unpaused chunk synchronously while checking pressure between physical lines. The previous async generator let RPC continuations resume between a reply and later completion notifications in the same chunk. The Codex completed-child regression reproduced this stale snapshot and now passes. CR/LF normalization and retained paused suffixes remain bounded.
- Events retain their 1 MiB splitting budget. Generic service replies allow the client's 2 MiB frame budget, so large service results can reach the client within their envelope budget.
- Client snapshot parent indexes are rebuilt from retained agents. Active entities can exceed the recent-history budget. Two legacy tests incorrectly expected a fatal hard entity cap; they now require live work and its parent relation to remain visible above that soft budget.
- Replay fallback verifies exact large-item text using the merged output stream API. Inline transcript parts are previews after #90, so a test expecting the full 700 KiB text inline was incorrect.
- Usage replay accepts same-thread agent reannouncement without replacing the run or cumulative counter history. It rejects cross-thread identity reuse. The account-restart failure was reproduced as a duplicate usage-agent primary key, and a public UsageStore regression failed before the fix. That regression also checks run-scoped cumulative totals and transaction rollback on cross-thread reuse.

`bunx vitest run` over only the twelve named files passed **92 tests** in 68.90 seconds. The strengthened usage-counter case was rerun separately and passed with the account restart case. No wall-clock sleeps or `setImmediate` assertions were added to these tests.
