# Native computer-use search transport

Measured 2026-10-23 on macOS 26.2 against the signed helper from `caf29ba57`.
The owned native fixture exposes 400 text fields, mostly containing long ASCII
values. Both helpers operate the same disposable background window through the
public computer toolkit. Measurements exclude model inference and network latency.

## Change and boundaries

`screen_state` sends a versioned search hint to the native helper. A lazy index of
the latest complete outline selects candidate nodes and their ancestors before
JSON serialization. The daemon still applies its canonical formatter and search,
so match counts and rendered results retain their existing semantics. Unicode
queries return the full tree; Unicode lines are retained conservatively for ASCII
queries. Unknown format versions fall back to the full tree, as do older helpers.

The index is invalidated on every new walk, including partial walks. Existing AX
walk freshness rules remain in charge. This reduces transport and formatting work;
it does not make AX traversal incremental or skip reading the tree after changes.
Full internal node references, screenshot marks and caller diff baselines remain
available after a search. A narrow result does not trigger the warning intended
for windows exposing almost no accessible content.

## Results

Twelve warm samples per query in the final forward run:

| Query            | Baseline median | Updated median | Baseline reply | Updated reply |
| ---------------- | --------------: | -------------: | -------------: | ------------: |
| `target invoice` |         7.46 ms |        6.73 ms |      655,883 B |       1,342 B |
| `Value: row 2`   |         6.80 ms |        7.48 ms |      655,883 B |     181,733 B |
| `text field`     |         7.57 ms |        8.76 ms |      655,883 B |     655,905 B |
| `missing record` |         7.26 ms |        5.22 ms |      655,883 B |       1,118 B |
| Unicode query    |         6.67 ms |        8.23 ms |      655,883 B |     655,905 B |

Narrow search cuts helper pipe data by 99.8%. This is transport data, not a
reduction in model-facing text: the returned search text was identical across
helpers and all samples. The first search after a full look, including index
construction, took 8.19 ms baseline and 8.55 ms updated. Broad queries and Unicode
fallback do not establish a latency improvement. Sparse-search p95 was also worse
in this run, 11.19 ms to 12.25 ms.

An earlier comparison with helper order reversed measured the updated narrow
search at 6.53 ms and the baseline at 11.18 ms. These local timings vary with run
order and load; the consistent result is the reduction in serialized data for
sparse ASCII matches. No universal search latency improvement is claimed.

Raw reports are not kept in the repository. The forward run and an earlier run with
the helper order reversed both used isolated signed bundle copies with identical
extra benchmark metadata and the same signing identity.

Screenshot capture, encoding and marking code is unchanged. JPEG encoding measured
about 2.6 ms with either existing NSBitmapImageRep or an experimental ImageIO path;
300 synthetic marks took about 4.9 ms. Neither experiment justified a change.
Removing screenshot-only metadata reads also failed to establish a reliable win
and was reverted. Sequential capture medians varied substantially across runs.
The final alternating-order comparison measured 36.81 ms baseline and 35.51 ms
updated, with byte-identical images across all 60 samples. Sequential images were
available but not all byte-identical across the fixture edit/restore boundary.
These results do not establish a capture speedup or regression.

## Verification and reproduction

The real fixture checks identical search text, unknown-format fallback, retention
of every original control ID, and background isolation. It changes one owned
field, verifies the old value disappears from search and the new value appears,
then restores it. An isolated helper with index invalidation removed fails this
check with `Search reused stale content after editing`.

```sh
ACE_CU_BASELINE_HELPER=/path/to/baseline/ace-screen-helper \
ACE_COMPUTER_HELPER="$PWD/native/screen-helper/build/ace-screen-helper" \
node packages/screen/bench/search-fixture.ts
```

The runner compiles and ad-hoc signs its own uniquely identified disposable app,
opens a background window, runs reads and the owned edit/restore, then terminates
its processes and removes its temporary bundle. Helpers need existing macOS
permissions. It does not operate personal documents or install security policy.

The native suite passes 192 tests with one optional test skipped. The computer-use
TypeScript suite passes 53 tests with two optional native tests skipped. Shared
cross-language examples cover labels, escaping, actions, IDs and Unicode fallback.
Signed helper build and root typecheck pass. `bun run check` passes formatting,
protocol docs, lint, size, annotation and extension checks, then stops at existing
UI-style violations in `pair-device.tsx`, `update-restart-dialog.tsx` and
`turn-end.tsx`. Complete locked-Mac operation remains outside this optimization.
