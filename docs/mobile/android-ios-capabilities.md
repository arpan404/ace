# iOS-to-Android capability matrix (A00.01)

Reference: HEAD `b92d9d2618481dfd8c77a94c6bcab5a26fa61395`.
Plan: `docs/plans/android-ios-parity.md` (tasks A00–A15) with ledger
`docs/plans/android-ios-parity-progress.md`, both read locally.
iOS behavior below is sourced from `apps/ios/` source and `apps/ios/README.md` at HEAD,
not from older roadmaps or screenshots (supporting evidence only).
Android status is sourced from `apps/android/src/` and `apps/android/README.md` at HEAD.

Legend — Android: `ABSENT` (no implementation), `FIXTURE` (debug fixture display only),
`PARTIAL` (bounded subset). Evidence: `SRC` (iOS source read), `AND` (Android source read),
`DOC` (README/plan text), `GAP` (no covering plan task — newly discovered gap).
Grant: `paired-read` means the read itself needs no operate scope (view-only can read;
a paired-read label never implies every read needs operate). `operate-gated
(read-only-refused)` means `ClientModel.canOperate == false` (view-only grant, i.e.
pairing scopes without `operate`/`admin` per `apps/ios/Sources/Models/PairingLink.swift`
`Grants`) refuses or disables the mutation. `+Projects` / `+Accounts` are additive
pairing scopes shown only where currently supported (New-thread/project rows, provider
accounts row). Per-action Projects/Accounts enforcement audit pending against
native/service guards elsewhere; this column never invents a scope. `local-only` means
on-phone UI with no pairing grant and no operate implied.
