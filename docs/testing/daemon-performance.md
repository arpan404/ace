Static review checked worker admission before sending, generation guards during retirement, reserved close messages, auxiliary executor/import transaction ownership, in-memory database lifetime, queue byte release on all failure paths, unchanged SQLite durability modes, indexed history reconciliation, directory identity and reference ownership in shared settings watches, and bounded weak event encoding. It also checked the merged #82 workspace fences and history progress reporting. #84 is now merged through orchestrator commit `6abfe79e`; its permission wiring is preserved without refactoring.

The default notifications worker remains resident because it owns live presence, pending aggregation and transport acknowledgements. Reaping it without moving that state would change delivery semantics. Search retains two independently admitted lanes so transcript ranking cannot starve the palette. Different SQLite owners retain their databases and protocols; consolidation into one shared database/pool would require migration and durability design beyond this focused change.

Remaining verification: run the remaining behaviour tests once at merge, run the packaged history import and Claude fork paths, exercise slow-client delivery with several subscribers, check watcher fallback and overflow on Linux as well as macOS, and calibrate the performance gate on CI. `check:deps` passes with an existing dependency-cruiser warning that TypeScript 7 is outside its supported compiler range; that limits its coverage.

## Merge failure repairs

The output owner now uses `maxQueuedBytes` as the one absolute queued-plus-transport cap for every event, snapshot, settings and control frame. It reserves bytes before enqueue or send and keeps unsent batch charges during flushing. `hardLimit` is only the sustained transport-pressure threshold, with its existing timeout. The settings cap regression uses a real settings service and a capacity that admits welcome but rejects its settings result. The separate authorized pressure tests retain their temporary-pressure assertions. The standalone control-cap test was updated to select the same capacity but was not run under this exception.

Socket input remains owned solely by #86's byte-based `SocketInput`. Its pause/resume thresholds, per-socket/global charges, pre-auth listener/address admission, hello deadline, Origin restriction and correlated command errors are preserved. None of the former eight-frame input budget is restored. Those security regressions need run at merge because their files were not authorized here.

OpenCode's wrapper previously released its server lease in `finally` even when the session rejected an idle close as unsettled. The process is now released only after successful close or confirmed exit. The existing lifecycle regression verifies refused closure leaves the account server reachable and the default instance usable.

History subscribers now receive a notification for already pending dirty paths. Authoritative scans consume the prior batch before scanning and retain events arriving during the scan. Overflow discards the unusable path batch immediately and requires full verification. The overflow test injects only native watch callbacks instead of assuming 4,100 writes produce 4,100 callbacks. New regressions use a real worker exit barrier, retained SQLite results and a held progress observer during shutdown. Late progress completion cannot send into a closed worker.

Mutation cases added by these repairs remain not executed: treat sustained pressure as instantaneous capacity; bypass the shared cap for controls/settings; release unsent batch charges too early; release a rejected idle-close lease; suppress already-dirty subscription notification; retain the prior batch after an authoritative scan; clear changes arriving during a scan; retain paths after overflow; send a late progress acknowledgement into a closed worker. Only the original full suite at merge can establish whole-repository execution coverage.
