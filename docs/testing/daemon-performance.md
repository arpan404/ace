## Merge failure repairs

The output owner now uses `maxQueuedBytes` as the one absolute queued-plus-transport cap for every event, snapshot, settings and control frame. It reserves bytes before enqueue or send and keeps unsent batch charges during flushing. `hardLimit` is only the sustained transport-pressure threshold, with its existing timeout. The settings cap regression uses a real settings service and a capacity that admits welcome but rejects its settings result. The separate authorized pressure tests retain their temporary-pressure assertions. The standalone control-cap test was updated to select the same capacity but was not run under this exception.

Socket input remains owned solely by #86's byte-based `SocketInput`. Its pause/resume thresholds, per-socket/global charges, pre-auth listener/address admission, hello deadline, Origin restriction and correlated command errors are preserved. None of the former eight-frame input budget is restored. Those security regressions need run at merge because their files were not authorized here.

OpenCode's wrapper previously released its server lease in `finally` even when the session rejected an idle close as unsettled. The process is now released only after successful close or confirmed exit. The existing lifecycle regression verifies refused closure leaves the account server reachable and the default instance usable.

History subscribers now receive a notification for already pending dirty paths. Authoritative scans consume the prior batch before scanning and retain events arriving during the scan. Overflow discards the unusable path batch immediately and requires full verification. The overflow test injects only native watch callbacks instead of assuming 4,100 writes produce 4,100 callbacks. New regressions use a real worker exit barrier, retained SQLite results and a held progress observer during shutdown. Late progress completion cannot send into a closed worker.

Mutation cases added by these repairs remain not executed: treat sustained pressure as instantaneous capacity; bypass the shared cap for controls/settings; release unsent batch charges too early; release a rejected idle-close lease; suppress already-dirty subscription notification; retain the prior batch after an authoritative scan; clear changes arriving during a scan; retain paths after overflow; send a late progress acknowledgement into a closed worker. Only the original full suite at merge can establish whole-repository execution coverage.

## Size-limit conductor plan delivery

The original timeout was reproduced with a diagnostic close-code and byte trace. Four roughly 1 MiB conductor views filled the ws transport buffer. The next frame found 3,148,749 transport bytes plus 1,049,577 frame bytes above the unchanged 4,194,304-byte capacity and closed with 4009. The fixture request listened only for its reply, so socket closure left it pending until the test timeout. SQLite and workers were not the blocked edge in this reproduction.

Output now stops transferring queued frames to ws above the soft transport threshold and resumes on successful send completion. Pending frames and transport bytes still share one absolute capacity; non-replaceable replies are never dropped. Unsent `conductor.changed` frames are complete snapshots and are replaced only for the same subscription, moved after intervening replies/events. An insertion-ordered queue and snapshot lookup keep append, replacement and dequeue work constant per change. Both maps are emptied on drain/close and bounded by admitted bytes. Input admission and #86 security behavior are untouched.

The size-limit plan equality assertion and timeout remain unchanged. The added real-WebSocket regression injects transport pressure, submits a burst of size-limit views around a get reply and another subscription, and checks the complete latest views, reply ordering and successful post-drain pong. It also checks non-replaceable replies still close at the same byte cap. The fixture now rejects requests and removes their listeners when the socket closes or errors.

Mutation cases for this regression: ignore soft pressure; omit send-completion drain; retain superseded snapshots; replace another subscription; retain the old snapshot's charge; reorder a newer snapshot before an intervening reply; drop replies; bypass the absolute cap for replies. These mutation cases are not executed (tests run at merge). The deterministic pre-fix regression run is a normal diagnosis run of the authorized file, not a mutation sweep. Remaining output/security regressions need run at merge under the owner's rule.

The requested consecutive run used the unchanged repository timeout and no filters: `bunx vitest run apps/daemon/src/conductor/admission.process.test.ts`, ten executions, eight tests each, zero failures. [Run counts](../../apps/daemon/bench/conductor-repeat.json) record durations. The original size-limit assertion passed ten of ten times. Typecheck, lint and scoped formatting passed after the fix. No other tests ran in this continuation.
