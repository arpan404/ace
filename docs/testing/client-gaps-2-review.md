## Static performance review

Root admission uses indexes on canonical workspace roots and session cwd. It does not read event or transcript history. Branch changes inspect at most 256 current root owners across at most eight reserved roots; larger operations reject before Git mutation. Older path aliases are reconciled at startup. A send uses indexed root-fence lookups. Services canonicalize before cache admission, retaining at most 64 file owners.

File controls retain at most eight pending operations and four channel/close lifetimes. Cleanup invalidates existing tokens immediately and creates no unbounded cancellation registry. A source advances after its durable ACK; a consumer requests its next chunk. A chunk contains at most 65,536 decoded bytes or 87,384 base64 characters. Eight queued chunks therefore contain at most 699,072 base64 characters, before bounded socket envelopes and parser overhead. These are limits derived from code, not measured RSS or latency.

Git classification processes all stderr with linear work in the diagnostic byte count. It retains an 8,192-character line tail and at most 64 hook identities, separate from the 65,536-byte diagnostic capture. Each decoder slice is at most 4,096 bytes. Trace records never enter the text fallback; a hook needs a nonzero child exit or explicit failure text.

Preview admission retains at most eight thread entries and 32 pending transitions per tab. Transitions serialize per thread. Session generation lookup and frame replay do not scan frame history.

No benchmark numbers were collected. A benchmark run would violate the owner's explicit ban. Chunk throughput, peak RSS, root admission latency at representative owner counts, noisy diagnostic parsing latency and concurrent Preview ordering **need run at merge**. The same applies to the review's serial/concurrent flakiness runs and mutation executions.
