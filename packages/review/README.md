# @ace/review

Local review sessions backed by SQLite and immutable git revisions. This deliverable supplies the backend and host execution ports. The standalone daemon has no production reviewer/fix executor or whole-tree completion subscription yet, so its agent actions reject as unavailable until the engine supplies both. Provider delivery belongs to that engine integration.

`ReviewWorker(path, executor?, options?)` is the daemon-facing API. `handle(command, worktree?, target?)` accepts the shared command envelope, owns effect retry receipts and returns `CommandResult.review`. Supply a host-resolved worktree for `review.open`; executor commands require a host-resolved `ReviewExecutionTarget` with thread id, workspace id and worktree. Both workspace and canonical worktree must match the saved session. `ReviewService` provides the same API directly for hosts already running off the event loop, with injected clocks and ids. Its injected GitService is owned by the service.

The protocol exports session sources, line positions, fingerprints, comments, replies, `ReviewerOutput`, `ReviewFixIntent` and `ReviewReviewerIntent`. Commands are open, comment, reply, resolve, applySuggestion, sendToAgent, askReviewer, refresh, status and list. List sessions without sessionId, comments with sessionId, and replies with both sessionId and commentId. The last id is the next cursor; an empty page ends iteration.

`ReviewExecutor.fix(intent, signal)` must durably accept and deduplicate the request id. Both intents carry immutable source revisions, source workspace/thread identity and the host's worktree. The engine must check that identity before provider delivery, then call `worker.afterFix(sessionId, requestId)` after its whole agent tree settles. This compares the saved target revision to a new worktree checkpoint and marks touched comments addressed-pending-review. `ReviewExecutor.review(intent, signal)` starts a reviewer run and returns its JSON object. Review validates and imports findings atomically. Executors must settle cancellation and cleanup before their promises finish. Neither action changes canonical agent status.

`anchorComment`, `anchorComments` and `reanchorComments` are pure. Re-anchoring takes the transition between the old and new revision of the comment's own side. Pass old-side comments the base-to-base transition, and new-side comments the target-to-target transition. Immutable source refs are stored at open and refresh. Deleted or ambiguous findings keep their last position and become outdated; changed findings require human review. Original anchor evidence never changes.

Limits: 1 MiB complete diff, 1,000 comments per session, 100 replies per comment, 100 reviewer findings, 100 selected lines, 8,192 fingerprint characters and 16 outstanding worker commands. Fix requests select at most 20 comments, carry 2,048-character excerpts and fit within 64 KiB of UTF-8 JSON. Reviewer runs accept at most 64 KiB of diff. Oversized inputs fail instead of silently truncating suggestions or findings. Lists return at most 20 records. Historical sessions remain on disk without an in-memory cache. Git's checkpoint counter cache retains at most 128 namespaces by default, with durable reload after LRU eviction; Git calls have a 64-call admission cap.

SQLite and git cannot share an atomic transaction with filesystem effects or engine acceptance. A crash after an operation starts leaves a receipt that returns `review_recovery_required` on retry. Completed receipts survive restart. Session deletion and automatic recovery are future work. Fingerprints preserve Git's no-final-newline metadata. EOF suggestions preserve an absent newline unless replacement text explicitly ends in a newline; a human edit to selected EOF termination conflicts. Older fingerprints remain schema-compatible, but cannot infer missing EOF metadata without a fresh anchor.

Read-only list requests remain available while an executor is waiting. Mutations serialize, with bounded backpressure. `recover(command)` only reads an effect receipt and never begins unknown work. The authenticated daemon reserves ids in its main receipt store before dispatch, so retry ids are shared with ordinary commands. Busy retries preserve existing pending reservations; a new request rejected before admission releases its reservation. Transient recovery results never overwrite a later durable completion.

Await `worker.close()` and `service.close()`. Closing rejects further work, aborts executor observers, kills and drains owned Git process groups, waits admitted work, then closes SQLite. Worker close also awaits parent-side executor cleanup before resolving. Started canceled effects retain recovery-required receipts. Worker spawners and the Git executable are injectable at the host boundary. Worker termination never bypasses Git draining.

The daemon starts a worker in its private data directory. It resolves registered workspaces and validates thread ownership. `startDaemon` exposes `review.afterFix` and accepts `{ executor, threadWorktree }` as its sixth argument. `createDaemonReview` accepts the same options with a thread-worktree resolver for hosts with isolated thread worktrees. A read-scoped device can list; mutations require operate scope. Clients cannot choose filesystem paths.

Tests and benchmarks run at merge, per the repository owner's rule. The anchor benchmark covers 1,000 comments across a 10,000-line transition. `benchmark:sessions` measures throughput, peak RSS, periodic RSS and retained checkpoint counters across 1,000 standalone reviews. Neither has timing assertions. Mutation cases are documented in `bench/mutations.md`; final runtime behavior and measurements need run at merge.
