# Governance

ace uses maintainer-led governance. The project is early, so decisions optimize for reliability, performance, security, and a maintainable architecture over broad feature growth.

## Decision Making

The maintainer makes final decisions on:

- project scope and roadmap
- accepted provider integrations
- protocol and architecture changes
- release timing
- security handling
- repository automation and review rules

Discussion is welcome, but maintainers may close or defer proposals that are too broad, hard to maintain, or not aligned with current priorities.

## Project Priorities

1. Performance.
2. Reliability.
3. Predictable behavior under load, restarts, reconnects, and partial streams.
4. Maintainability.
5. Cross-platform user experience.

When these conflict, correctness and robustness take priority over short-term convenience.

## Contributor Path

The best path to larger contributions is:

1. Start with focused fixes, tests, docs, or reproducible bug reports.
2. Discuss larger changes in an issue before implementation.
3. Keep PRs small enough to review.
4. Follow maintainer feedback on scope, tests, and architecture.

Regular high-quality contributions may be recognized with trusted contributor status in review and labeling workflows.
